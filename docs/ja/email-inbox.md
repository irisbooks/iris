# メールで書類を取り込む

クラウドの帳簿には、1冊ごとに専用の受信アドレスがあります。領収書や請求書を
このアドレスに送るか、自分のメールから転送すると、本文と添付ファイルが自動で
帳簿の `raw/` に保存されます。仕入先の請求書、オンライン購入のレシート、銀行からの
通知を、スキャナーも CLI も使わずに取り込めます。会社のメールなどの自動転送ルールは
隔離されることが多いので、[隔離されたメールの確認](#隔離されたメールの確認)の
注意を先に読んでください。

## 帳簿の受信アドレス

アドレスは帳簿を作ったときに決まり、年度が変わっても同じものを使い続けられます。
[`iris yearend`](cli-reference.md#iris-yearend) で翌年度の帳簿を作ると、
アドレスは新しい帳簿に移り、古い帳簿には別のアドレスが割り当てられます。
取引先に伝えたアドレスを変える必要はありません。アドレスは次のコマンドで確認します。

```bash
iris api inbox show <book-id>
```

`k7f3x9q2m4p8w1r5@in.irisbooks.io` のような形式です。推測されてスパムを
送られないよう、ランダムな文字列にしています。むやみに公開せず、帳簿に
取り込みたいメールの送信元（取引先やサービス）にだけ伝えてください。

## 受け付けられる条件

メッセージは、次の**すべて**を満たしたときにだけ取り込まれます。

1. **送信者が帳簿の許可リストに載っている**（後述）。
2. **送信サーバーの検証に合格している** — 差出人が本物かを確かめる3つの検証
   （SPF・DKIM・DMARC）にすべて合格していること。差出人（From:）を偽装した
   メールは帳簿に入りません。
3. **ウイルススキャンで問題が見つからない** — すべてのメッセージを、帳簿に
   保存する前にスキャンします（GuardDuty マルウェア保護）。

条件を満たさないメッセージは隔離リストに入ります。通知なしに破棄することは
ありません。

## 帳簿に入るもの

受け付けたメッセージは、1通ごとに `raw/email/` の下の1フォルダになります。
フォルダ名は月とメッセージ ID です。

```
raw/email/2026-07/a1b2c3d4e5f6g7h8/
├── email.md          # 差出人・宛先・日付・件名 + 本文テキスト
├── receipt.pdf       # 添付ファイル（そのまま開いて参照できる）
└── invoice-0042.pdf
```

`email.md` の先頭には、送信者・日付・件名・添付ファイルの一覧が入ります。AI は
これを読んで経緯をつかみ、添付ファイルを元資料として参照する仕訳を作れます
（仕訳の `attachments` の `path` にファイルのパスを書きます。
[基本コンセプト](concepts.md) を参照）。これらのファイルはまずクラウドに保存され、
次の `iris sync` で手元のフォルダに届きます。

10MB を超える添付ファイルは保存されず、その旨が `email.md` に記録されます。
元のメッセージは、監査用の控えとしてサーバーに保管されます。

## 送信者許可リストの管理

許可リストには、最初からあなたのログイン用メールアドレスが入っています。
そのため、自分のメールからの転送は設定なしで受け付けられます。送信者は、
アドレス1件でも、ドメイン全体でも追加できます。

```bash
iris api inbox allow billing@stripe.com <book-id>   # このアドレスだけ
iris api inbox allow '*@amazon.co.jp' <book-id>     # ドメイン全体
iris api inbox disallow '*@amazon.co.jp' <book-id>  # 許可を取り消す
```

追加と削除ができるのは、帳簿のオーナーと記帳担当です。フラグの一覧は
[CLI コマンドリファレンス](cli-reference.md) にあります。[Web アプリ](web-app.md) の
**帳簿の設定 → メール取り込み** でも、アドレスの確認と許可リストの管理ができます。

## 隔離されたメールの確認

受け付けなかったメッセージは、理由とともに一覧で確認できます。Web アプリでは
**帳簿の設定 → メール取り込み** に表示され、隔離された送信者をその場で許可できます。
CLI では次のコマンドを使います。

```bash
iris api inbox quarantine <book-id>
```

| 理由 | 意味 |
| --- | --- |
| `sender_not_allowlisted` | 送信者が許可リストにありません。許可リストに追加し、もう一度送ってもらってください。 |
| `auth_fail` | 送信サーバーの検証（SPF・DKIM・DMARC）に失敗しました。差出人の偽装か、自動転送ルールによる書き換えが考えられます。 |
| `malware` | ウイルススキャンが脅威を検出しました。メッセージは帳簿に保存されていません。 |
| `scan_failed` | スキャンを完了できませんでした（例: パスワード付きの圧縮ファイル）。パスワードを外して送り直してください。 |
| `ingest_failed` | 3つの条件は満たしましたが、帳簿への保存に失敗しました。もう一度送ってください。 |

**自動**転送ルールには注意が必要です。会社のメールなどで、元の送信者のまま
再送するルールを使うと、送信サーバーの検証に合格しなくなることがよくあります。
この場合、送信者が許可リストにあっても `auth_fail` で隔離されます。自分のメール
ソフトで1通ずつ手動で転送すれば、あなたが送ったメールとして検証されるので
受け付けられます。

# CLI と自分の LLM で記帳する

このページでは、帳簿のファイルを中心にした記帳の進め方を説明します。自分の AI
アシスタント（Claude、Cursor、Copilot など）が帳簿のファイルを読み書きし、`iris` CLI が
検証と集計を行います。仕訳などの記録は Markdown ファイルで、先頭に YAML 形式の項目
（フロントマター）が付きます。設定は YAML ファイルです。`iris` 自体はアカウントも
ネット接続も要りませんが、AI サービスには接続が必要な場合があります。

初めて読むときは、[全体イメージ](#全体イメージ)、
[最初の一度: AI をつなぐ](#最初の一度-ai-をつなぐ)、[毎日のループ](#毎日のループ)の
3節で足ります。残りの節は、必要になったときに読んでください。

## CLI の利用とサポート

`iris` CLI は無料で、**現状のまま（as is）**提供します。動作や出力の正確さ、
個別サポート、不具合の修正、継続的な更新は保証しません。出力は自分で確認し、
帳簿は別途バックアップしてください。質問や不具合の報告は
[Discord コミュニティ](https://discord.gg/wZDsv9gyb9)へお寄せください。回答は保証しません。

## 全体イメージ

作業を始める前に、最終的に何が必要かを AI と確認します。仕訳を残したいのか、
数字を確認したいのか、資料と説明をまとめて誰かに引き継ぎたいのかで、進め方が
変わるためです。資料が足りなくても、元資料へのリンク、確認済みの事実と
仮の金額、未解決の質問、次の作業を引き継ぎメモに残せます。何を用意すれば
役立つか分からない場合は、AI に提案してもらいます。

そのあとの作業は、次の4段階です。

1. 資料を渡す、AI が読めるファイルの場所を伝える、起きたことを話す。
   必要なツールとアクセス権があれば、明細の取得も AI に頼めます。
2. **AI** が元資料を帳簿内の `raw/` に保存し、内容を読み取り、**仕訳**と説明を提案する。
3. **`iris`** が構造と計算を検証し、レポートを計算する。
4. **あなた**が内容を確認し、承認するか質問する。通常は確認後に記帳します。
   自動記帳を認めている場合は、その帳簿で選んだ方針に従います。

AI は判断と説明、`iris` は検証と計算を担います。手作業でファイルを整理したり、
形式を覚えたりする必要はありません。`iris` の検証が確かめるのは、
決められたルールに合っているかどうかです。AI が資料を正しく読み取ったかどうかまでは
確かめられません。

作業が一区切りしたら、AI に次の2点を説明してもらいます。保存した記録や計算結果の
うち、今使えるものは何か。目的を達成するまでに、あとどんな資料・確認・外部での作業が
必要か。用意できたものと使い道の対応は、次のとおりです。

| 用意できたもの | 今できること |
| --- | --- |
| 元資料とノート | 資料や確認済みの事実を保存し、確認や再開に使えます。仕訳を作る前でも保存できます。 |
| 下書きの仕訳（draft） | 提案内容を確認できます。通常の会計レポートには含まれません。 |
| 記帳済の仕訳（posted） | 対象の帳簿・期間のレポートに反映されます。申告書の作成・提出は別の作業です。 |

資料が足りない場合も、確認できた内容は保存し、不足する情報をノートに残します。
次に誰が何をすればよいかを AI に説明してもらい、詳しいチェックリストは帳簿と
一緒に保存します。`iris validate` が確認するのは、
記録の構造と、選択したルールに合っているかどうかです。会話の中で行った計算が正しいか、
資料がすべてそろっているか、申告書が完成しているかは確認しません。

## 最初の一度: AI をつなぐ

AI が CLI を実行でき、帳簿を読み書きできるなら MCP の登録は不要です。MCP 接続を
使いたい場合や、不足するローカルの案内を追加したい場合に `iris onboard` を実行します。

```bash
iris onboard
```

`iris onboard` は、`iris` の各コマンドを AI が道具として呼び出せるようにする小さな
サーバー（`iris mcp serve`）を、MCP 対応の AI アプリに登録します。あわせて Claude Code
スキルを書き込みます。Claude Code には必ず登録し、Claude Desktop・Codex・Cursor・
Gemini CLI・VS Code には、インストールされている場合に登録します。登録すると、AI は
帳簿の状態を推測する代わりに、検証（`validate`）・差分（`diff`）・残高（`balance`）・
レポート（`report`）・状態確認（`status`）を `iris` に直接問い合わせられます。
サインイン後は同期（`sync`）も呼び出せます。

現在の接続状態は `iris onboard --status` でいつでも確認できます（AI 向けには
`--json` を追加）。`iris onboard` の再実行は常に安全で、登録はその場で更新され
ます。すべて元に戻すには `iris offboard` を実行します。登録とスキルだけを削除し、
帳簿やサインインには触れません。

この接続設定は、帳簿のフォルダがあるパソコンのためのものです。クラウドにリンクした
帳簿なら、外出先でも同期済みの記録やレポートを読めます。リモートコネクタは読み取り専用で、
変更にはローカルの環境を使います。
[外出先の AI から帳簿へ（リモートコネクタ）](remote-connector.md)
を参照してください。

新しい帳簿のフォルダ直下には、英語で書かれた短い作業ガイド `AGENTS.md` が入ります。
AI はこれを読んでから作業します。内容は、記帳ポリシー、データを守るルール、最小限の
仕訳例、資料の調べ方です。帳簿を CLI・MCP で作っても、Web・API で作っても、同じ
ひな形が使われます。`AGENTS.md` は帳簿と一緒に同期され、`iris clone` で複製した
帳簿にもそのまま入ります。内容を変更できるのは帳簿のオーナーで、クラウド上で
変更する場合もオーナー権限が必要です。

同じ場所にある `README.md` はフォルダの説明、`CLAUDE.md` は `AGENTS.md` を読むよう
AI に伝える案内です。以前の `iris` で作った帳簿では、`iris onboard` が足りないガイドを
追加し、既存の `LLM-GUIDE.md` に書かれた方針を `AGENTS.md` に引き継ぎます。自分で
書き換えたガイドは上書きしません。

> **AI が隔離された環境で動く場合**（`iris` が入っていない VM など）: 帳簿の
> フォルダに `iris` の実行ファイルは入っていません。あなたのパソコン（ホスト）の
> MCP を使う場合は、ホスト側で `iris mcp serve` を実行し、AI は同じフォルダに対して
> そのツールを呼び出します。顧客の帳簿を扱うときは、ホストへの接続も
> [顧客ごとのアクセス範囲](#税理士も顧客ごとの作業フォルダで記帳する)に限定してください。

Cowork の `.mcpb` 拡張では、**帳簿をまとめる親フォルダ**（例: `~/IrisBooks`）を
選び、各帳簿をその直下の子フォルダに置きます。Cowork にも作業するフォルダへの
ファイルアクセスを許可してください。親フォルダが空でも起動でき、AI に
`create_book` で帳簿を作るよう依頼できます。AI は `list_books` で帳簿を確認し、
各操作で対象の帳簿を指定します。子フォルダに帳簿を追加するたびに MCP の共通設定を
変更する必要はありません。手動で設定する場合は
`iris mcp serve --books-dir ~/IrisBooks` を使います。`--book-path PATH` も引き続き
1つの帳簿に使えます。[MCP コマンド](cli-reference.md#iris-mcp)も参照してください。

税理士の作業では、親フォルダに1社の帳簿だけを置きます。たとえば、
`~/IrisBooks/ClientA/2026` と `~/IrisBooks/ClientA/2027` を置き、顧客Aの
AI の接続先は `~/IrisBooks/ClientA` にします。クラウドの認証情報の範囲も
別途確認してください。会話を分けるだけではアクセスは制限されません。

## 毎日のループ

[全体イメージ](#全体イメージ)の4段階を、コマンドとあわせて順にたどります。

### 1. AI に情報を渡す

銀行CSV、領収書の画像、PDF 請求書をチャットに添付するか、AI が読める
フォルダの場所を伝えます。必要なツールとアクセス権を与えて取得を頼む方法も
あります。元資料の `raw/` への保存は AI に任せられます。自分で置きたい場合は、
日付別・取引先別などのサブフォルダも自由に使えます。家計の現金支出なら、
資料なしで、残高と短い聞き取りから始めることもできます。

### 2. AI に処理させる

アシスタントに「この明細を記録して」「最近の家計の現金支出を整理したい」などと
頼みます。`AGENTS.md` に従い、AI は次を行います。

- 資料がある場合は全文読み、`notes/raw/<source>.md` に**パースキャッシュ**を書きます。
  各行を `journaled`・`ignored`・`deferred` で記録した恒久的な表です。あとで同じ
  明細を開き直しても作業をやり直さずに済みます。
- 聞き取りの場合は、伝えた内容や推定の根拠を仕訳の本文やノートに残します。
- 希望する詳しさに合わせて、`journals/YYYY-MM/…-NN.md` に `status: draft` の仕訳を提案します。
- 事業の判断で未解決の点や重要な不明点は `notes/open-questions.md` に記録します。
  家計の推定額や推測した分類も明記します。

### 3. 検証する

```bash
iris validate
```

すべてのファイルについて、次の点を確認します。

- YAML として読める
- 借方と貸方の合計が一致している
- 使っている科目が勘定科目表にある
- 日付に矛盾がない
- ステータスが正しい
- 帳簿で選択したオーバーレイのルールを満たしている

エラーが出たら、直して再実行します。原因の多くは、勘定科目表にない科目か、貸借の
不一致です。この繰り返しは AI に任せられます。

`iris validate` の末尾に「同期キューでブロックされたファイルがある」旨の注記が
出た場合は、ファイルに問題があるのではなく、サーバーが同期を拒否しています。
[トラブルシューティング](troubleshooting.md) を参照。

### 4. レビューして帳簿を読む

```bash
iris balance                         # 本日時点の試算表（記帳済のみ）
iris report pl --from 2026-04-01 --to 2026-06-30
iris report bs --as-of 2026-06-30
iris search --payee amazon --from 2026-04-01     # 仕訳を検索
iris references raw/2026-05-invoice.pdf                # この資料を引用する仕訳
```

AI が帳簿のフォルダを直接読み書きできる場合、ファイルの一覧・読み取り・文字列検索と、
下書きやノートの編集には、通常のファイル操作の道具（`rg`・`grep`・`find`・`cat`・
`sed` やエディタ）を使います。操作は選択した帳簿の中にとどめ、記帳に関わるファイルを
編集したら必ず検証します。ローカル MCP は、会計計算・検証・認証・同期と、記帳・締め・
償却・翌年度の帳簿の作成といった専用の処理に使います。検索などの参照用ツールは補助で、
条件を組み合わせた検索、締め済みかどうかを含めた検索、ファイルを直接読めない
AI アプリで役立ちます。

`iris search` と `iris references` は、オフラインでも使えます。

同じレポートや仕訳を画面で見るには、帳簿のフォルダで `iris view` を実行します。
詳しくは[このパソコンで帳簿を開く](iris-view.md)を参照してください。

### 5. 記帳する

下書きは、記帳するまで各種レポートや残高に反映されません。内容に納得できたら
記帳します。

```bash
iris post journals/2026-05/2026-05-04-example-com-01.md
```

`iris post` は、ファイルを検証し（中身があること、貸借が一致していること）、
`status` を `posted` に書き換えます。クラウドにリンクした帳簿なら、続けて同期します。
`--dry-run` を付けると、何も変更せずに結果だけ確認できます。`status:` を手で
書き換えても記帳できます。`iris post` を使うと、貸借のチェックと同期までまとめて
行われます。

[`iris view`](iris-view.md) から記帳することもできます。下書きを開いて内容を確認し、
**記帳**を選びます。記帳されるのはこのパソコンの上だけで、`iris post --local` と
同じです。クラウドにリンクした帳簿なら、次の同期でクラウドに反映されます。

## 家計は無理なく続けられる詳しさで

日々の私的な支出は、役に立つ範囲で記録すれば十分です。領収書をすべて残す
必要はありません。たとえば、今の手持ち現金を AI に伝えます。
すると AI が、前回の確認から何に使ったかを大まかに質問します。このとき、現金の補充や
口座間の移動があったかも確認します。カードや銀行の明細がある場合は、金額は明細の
とおりに使い、用途は AI に大まかに分類してもらえます。
推定や使途不明の差額は明記し、架空の買い物で埋めないようにします。

事業の帳簿は、金額・日付・科目を正確にし、根拠となる資料も大切にします。
個人の記録でも、税務や経費精算に使うものは同じ扱いです。希望する記録の
詳しさは `notes/workflow.md` に、推定の根拠は仕訳の本文やノートに残すよう
AI に頼んでください。判断や質問もファイルに残るため、次の会話や別の AI に
作業を引き継げます。同期を使うと、クラウドのコピーとサーバー側の変更履歴も残ります。

## 税理士も顧客ごとの作業フォルダで記帳する

税理士・会計事務所にも、自分の AI と帳簿ファイルで作業する方法を勧めます。
顧客ごとに帳簿を保存するフォルダを分け、専用の AI セッションや VM には
その顧客のフォルダだけを渡します。たとえば、顧客Aの Cowork セッションには
顧客Aの必要な年度の帳簿だけを読み書きさせ、全顧客をまとめた親フォルダは渡しません。

顧客から共有された帳簿を、そのフォルダに複製（`iris clone`）し、自分の権限の範囲で同期します。
ガイドとノートを読み、修正案の作成・検証・記帳をその帳簿の方針に沿って進めます。
引き継ぎに必要な情報も顧客のファイルに残します。一時的な VM とは別に、
継続して保管できる場所にもコピーを持ってください。

フォルダを分けるだけでなく、AI につないだツールと認証情報が届く範囲も確認します。
ホスト側で共有している MCP サーバーは、指定したフォルダの外にあるクラウドの帳簿にも
アクセスできる場合があります。パーソナルアクセストークン（PAT）の役割も、アクセスを
顧客1社に限定するものではありません。事務所全体で使う認証情報や一括処理のツールは、
顧客ごとの AI セッションに渡さないでください。必要なら、複製と同期は別の環境で行い、
AI には対象のファイルと、ほかの顧客に届かないツールだけを渡します。設定したつもりの
範囲ではなく、実際に届く範囲を確かめてください。

[Web アプリ](web-app.md) はレポートの閲覧、レビュー、権限に応じた承認、履歴確認に
使い、ファイルでの作業を補います。

## オンラインにする（クラウド）

ローカルの帳簿をクラウドにリンクすると、Web アプリ、複数の端末からのアクセス、
共同作業、年度の締め、訂正・削除の履歴が使えるようになります。ここまでの作業の
流れは変わらず、`iris sync` が加わるだけです。

```bash
iris api login            # ブラウザでサインイン。このデバイス専用の CLI セッションが発行される
iris api whoami           # 実際に使う認証情報とAPI接続先を確認
iris api books new        # クラウド帳簿を作成…
# …または既存のものにこのフォルダをリンク:
iris api books link <book-id>
iris sync                 # 明示的な push + pull を1回
```

`iris api login` は、ブラウザが CLI を実行しているパソコンに応答を返せる環境で
使います。リモートの環境や画面のない環境、別のブラウザプロファイルで承認したい場合は、
`iris api login --device` を使います。自分の端末で承認したあと、
`iris api login --device-complete` を実行し、`iris api whoami` で確認してください。
「許可待ち」と表示されている間は、まだサインインは完了していません。[ログイン方式とアカウントの分離](cli-reference.md#iris-api-login)も参照してください。

承認の画面では、この CLI からアクセスできる帳簿を選びます。最初の帳簿や翌年度の
帳簿を CLI から作る場合は、**帳簿の作成を許可する**も選んでください。このサインインで
作成した帳簿には、同じ権限で自動的にアクセスできます。あとからほかの方法で追加された
帳簿には、アクセスできません。帳簿の選び方は、どのログイン方式でも同じです。翌年度の
帳簿を作る（`iris yearend`）には、元の帳簿のオーナー権限と、フルの操作権限が必要です。

リンクしたあとは、次のコマンドを使います。

- `iris sync` は、ローカルの変更をクラウドへ送り、クラウドの新しい変更（税理士が
  ファイルで作成して同期した仕訳など）を受け取ります。ファイルごとに、受け取られたか
  拒否されたかを報告します。
- `iris diff` は、次の同期で何が送られるかを、同期の前に表示します。
- `iris api history --path journals/2026-05/...md <book-id>` はファイルの
  訂正・削除の履歴を表示します。

クラウドにリンクしても、同期は**指示したときだけ**動きます。裏で自動的に動くことは
ありません。

## 固定資産と減価償却

減価償却する資産がある場合は、資産ごとに `assets/YYYY/<name>.md` を作り、取得価額・
耐用年数・償却方法を書きます。そのうえで次のコマンドを使います。

```bash
iris asset schedule                       # 各資産の償却計画を見る
iris asset depreciate --year 2026         # 資産ごとに期末の仕訳を 1 本
iris asset depreciate --month 2026-05     # 月次で締めるならその月の仕訳を生成
```

`iris asset depreciate` は提案仕訳（`status: draft`）を書き出すので、ほかの仕訳と
同様にレビューして記帳します。ファイル形式は
[帳簿ファイル形式リファレンス](book-format-reference.md)に、地域ごとの償却方法と
ルールは[オーバーレイ](https://irisbooks.io/docs/ja/overlays/)の地域ガイドにあります。

### 償却の計算は AI にさせず、iris に渡す

定額法は iris が自分で計算します。国ごとにルールが決まる方法（途中で償却率が
切り替わる定率法など）は進め方が違います。AI が償却率を調べ、方法が切り替わる時点を判断し、
計算は iris に渡して、出来上がった表を資産ファイルの `schedule:` に記録します。

そのために MCP 経由で次の資産ツールが使えます。

| ツール | 役割 |
| --- | --- |
| `asset_schedule` | エンジンによる資産別の数値。申告にはこの値をそのまま使う |
| `declining_table` | 指定した率での定率法の表 |
| `flat_table` | 償却し終わるまで一定額を計上する表 |
| `straight_line_table` | 基準額を N 期間で均等に割る表 |
| `list_recipes` / `run_recipe` | 地域オーバーレイに用意された組み合わせ。あればこちらを優先 |

ローカル MCP の接続先が帳簿1冊でも、帳簿をまとめた親フォルダでも、使い方は同じです。
まず `list_recipes` で、CLI と同じレシピ ID と入力形式を確認します。次に
`run_recipe(recipe=..., params={...})` で結果を表示します。結果を保存するときは、
`apply=true` と、帳簿からの相対パス `out` を追加します。`out` だけでは保存されません。
親フォルダに接続している場合は、`book` の指定も必要です。

この方法の要点は、AI が残高に率を掛ける計算を自分で繰り返さないことです。計算の
誤りはそこで起きます。しかも、合計が合ってしまう誤りは `iris` には見つけられません。
そこで、AI には計算をさせず、`iris` が作った正確な表を組み合わせてもらいます。

選択したオーバーレイにその方式の**レシピ**があれば（`list_recipes` に表示されます）、
AI はその ID で `run_recipe` を呼びます。レシピは決められた順序で表を組み立て、各行の
もとになった入力を記録します。そのため `iris validate` が再計算でき、償却方法の
切り替えが1年ずれた、といった誤りを検出できます。AI が表を自分で組み合わせるのは、
レシピのない方式の場合だけです。ファイル形式と、`iris` が検査する内容は
[`schedule:`](book-format-reference.md#schedule-計算させるか表を記録するか) を
参照してください。

## エクスポート

```bash
iris export                 # journals.csv, trial-balance.csv, ledger-*.csv
iris export --year 2026     # 会計年度で絞り込み
iris export assets          # 資産別の償却スケジュール
```

CSV は、日本語などの非 ASCII 文字を Excel が正しく開けるよう UTF-8（BOM 付き）で書き出します。
文字列のセル（取引先・摘要・タグ・勘定科目名・資産名）が `=`・`+`・`-`・`@` で
始まる場合は先頭に `'` を付けて書き出します。表計算ソフトが数式として実行せず、
文字列として表示するためです。金額のセルは変えません。
クラウドにリンクした帳簿では、`iris api history --all --json <book-id>` で
帳簿の（つまりその年度の）訂正・削除の履歴をファイルに書き出せます。

## 領収書の明細、家計の集計、過去分の追記

この節は、領収書単位の記録、家計の集計、あとから見つかった資料の追記を、実際の
ファイルで確かめるための詳しい例です。

記帳前に、残す詳しさを `notes/workflow.md` で決めます。
事業用の帳簿で領収書ごとの記録を選ぶ場合は、1仕訳に合計しても元の品目明細を保存してください。
日常の家計管理では、確認済みの支出総額を使い、分類の推定を明示して集計する方法もあります。
本人が決めた基準額以上の購入は別に記録し、費用として追跡するか、資産として管理するかを説明します。
事業用資産や税務の処理は、資産の手順と実際の要件に従います。家計の例の金額や分類からは判断しません。

例に使うのは、互いに関係のない2つの架空の帳簿（事業用と個人用）です。1つの支出を
2つに分けた例ではありません。どちらも通貨は JPY（小数なし）、会計年度は2026年1月〜12月で、
オーバーレイは選択していません。それぞれの勘定科目表で、預金と現金を資産、開始残高を
純資産、例に出てくる費用の科目を費用として定義してあるものとします。コードは記帳後の
形です。実際には、各帳簿の方針と自分の権限の範囲で下書きを作り、確認してから記帳します。
税務や立替精算に使う場合は、それぞれの資料要件も確認してください。
ここで領収書ごとに残すのは作業方針であり、すべての場合に一律で求められる法的要件ではありません。
地域の法令が求める内容は、[オーバーレイ](https://irisbooks.io/docs/ja/overlays/)の地域ガイドにあります。

### 領収書と口座明細が同じ支払を示す場合は1件にまとめる

事業用の帳簿の開始残高は預金100,000円、現金10,000円、純資産110,000円です。
1月5日の文具の領収書には2品目ありますが、支払は1件です。

```csv

2026-01-05,Synthetic Stationer,Paper,1000,JPY
2026-01-05,Synthetic Stationer,Pens,320,JPY
```

```yaml

date: 2026-01-05
```

1月12日のソフトウェア代3,300円は、領収書とカード明細が同じ利用を示します。
`Expenses:Software` を借方、`Liabilities:Card` を貸方に1回だけ計上し、両方の資料を添付します。
カード明細の各利用を既存の領収書仕訳と照合し、未記帳分だけを補います。
1月18日の鉄道代2,200円は領収書がなく、本人が日付・金額・支払者・業務目的を確認したとします。

```csv
date,merchant,amount,purpose,receipt_status
2026-01-18,Synthetic Rail,2200,Owner confirms client meeting travel,missing
```

```yaml
schema_version: 1
date: 2026-01-18
status: posted
tags: [no-receipt]
lines:
  - {account: Expenses:Travel, debit: 2200}
  - {account: Liabilities:Card, credit: 2200}
attachments:
  - {path: raw/cards/2026-01.csv, type: bank_statement, locator: L4}
  - {path: raw/statement-review.csv, locator: L2}
```

領収書がないこと（`no-receipt`）と、原本をまだ入手できていないことを、
`notes/open-questions.md` に書いておきます。利用額の根拠はカード明細で、目的の根拠は
本人の確認記録です。この管理用仕訳だけで請求書の適格性や必要経費への算入が決まるわけではありません。
取引内容や金額自体が不明なら、費用を推測せず、分類を保留して不足情報を確認してください。
後日の預金引落はカード債務の精算です。購入費用を再度計上しません。
1月20日の現金引出は `Assets:Cash` を借方5,000円、`Assets:Bank` を貸方5,000円に記録します。費用は発生しません。
後から見つかった1月28日の顧客向けフォルダの領収書1,100円は、`Expenses:Supplies` と現金で記録します。
発見・確認の経緯をメモに残し、取引日は実際の日付を使ってください。
家計の月次推定を事業の証拠に転用したり、ファイル名から税務上の適格性を決めたりしないでください。
家事按分は[形式リファレンス](book-format-reference.md#費用の事業分と家事分を分ける)の日付付き基準に従います。

### 家計の推定分類と大きな購入を区別する

個人用の帳簿の開始残高は預金200,000円、現金10,000円、純資産210,000円です。
1月10日に預金から現金へ10,000円を移します。
本人が1月の通常の現金支出総額9,000円を確認し、8,000円・1,000円の分類は推定とします。
個々の店名や取引日は分かっていません。

```csv
period_from,period_through,total_cash_paid,groceries_estimate,transport_estimate,currency
2026-01-01,2026-01-31,9000,8000,1000,JPY
```

```yaml
schema_version: 1
date: 2026-01-31
status: posted
lines:
  - {account: Expenses:Groceries, debit: 8000}
  - {account: Expenses:Transport, debit: 1000}
  - {account: Assets:Cash, credit: 9000}
attachments:
  - {path: raw/interview.csv, locator: L2}
```

1月31日は合意した集計期間の末日です。個々の購入日を推測しているわけではありません。
確認済み総額、推定した分類、対象期間、除外した取引を本文に残してください。
あとから正確な領収書が見つかり、集計の一部をそれで置き換える場合は、まず集計のうち
どの金額がその領収書に当たるかを確認します。そのうえで、その金額を集計から外して
領収書の仕訳に置き換えるか、科目を振り替えます。集計を残したまま領収書の仕訳を
追加すると、同じ支出を二重に計上することになります。
この簡略な記録は家計管理用であり、領収書単位の税務・立替精算の証拠にはしません。

本人が個別記録の基準を **50,000円以上** と決めたとします。
60,000円のソファは1月15日のカード購入として別に残し、現金とカードの両方の集計から除外します。
本人がこの個人用の帳簿で費用として追跡する方針を選んだ例です。事業の資産計上基準や税務処理を示すものではありません。

```csv
date,merchant,description,amount,currency
2026-01-15,Synthetic Furniture,Personal sofa,60000,JPY
```

```yaml
schema_version: 1
date: 2026-01-15
status: posted
lines:
  - {account: Expenses:Furniture, debit: 60000}
  - {account: Liabilities:Card, credit: 60000}
attachments:
  - {path: raw/receipts/sofa.csv, type: receipt, locator: L2}
  - {path: raw/cards/2026-01.csv, locator: L4-L5}
```

### 口座明細、処理状況、実際の行位置を残す

個人用のカード明細は `raw/cards/2026-01.csv` です。ソファの説明欄には引用符内の改行があります。
元資料の改行を消して整形しないでください。

```csv
date,description,charge,payment,balance
2026-01-01,Opening,0,0,0
2026-01-07,Synthetic Market,12000,0,12000
2026-01-15,"Sofa delivery
order S-15",60000,0,72000
2026-01-19,Synthetic Rail,8000,0,80000
2026-01-31,Closing balance,0,0,80000
```

個人用のカード集計には、スーパー12,000円と鉄道8,000円だけを含めます。
分類の推定は明示し、利用額は明細どおりに記録します。ソファ60,000円は除外します。
**集計20,000円＋個別購入60,000円＝明細の利用額80,000円** です。
ソファは実際の1月15日の日付と資料を保ちます。先の現金支出9,000円は別の集計であり、カード利用額には含めません。

```yaml
schema_version: 1
date: 2026-01-31
status: posted
lines:
  - {account: Expenses:Groceries, debit: 12000}
  - {account: Expenses:Transport, debit: 8000}
  - {account: Liabilities:Card, credit: 20000}
attachments:
  - {path: raw/cards/2026-01.csv, type: bank_statement, locator: L3}
  - {path: raw/cards/2026-01.csv, locator: L6}
```

パースメモの置き場所は、元資料のパスから決まります。`raw/` から始まるパスをそのまま
`notes/` の下に再現し、元の拡張子を残したまま末尾に `.md` を付けます。
`raw/cards/2026-01.csv` のメモは `notes/raw/cards/2026-01.csv.md` です。預金の明細も
同じで、`raw/bank/2026-01.csv` のメモは `notes/raw/bank/2026-01.csv.md` になります。

パースメモは AI が保守する作業記録です。自動取込の機能でも、重複を自動で防ぐ機能でも
ありません。処理済みの行に書いた仕訳への参照は、そのまま保ちます。開始残高・終了残高の
行は `ignored` とし、無視する理由を書きます。一方、内容の分からない出金を、処理を
終わらせるために `ignored` にしてはいけません。取引の事実が足りない行は `deferred` とし、
足りない情報を `notes/open-questions.md` に書いておきます。

```markdown
---
source: raw/cards/2026-01.csv
source_sha: sha256:9bfde1fbdc1a8cffcdf724cb867a3dd1980dabdf03efaa2734682bcbe386991b
parsed_at: 2026-10-24
counts: {total: 5, journaled: 3, ignored: 2, deferred: 0}
---

## Rows

| id | date | description | amount | status | target / reason | locator |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 2026-01-01 | Opening | 0 | ignored | Zero opening liability; no transaction | L2 |
| 2 | 2026-01-07 | Synthetic Market | -12000 | journaled | journals/2026-01/2026-01-31-card-summary.md | L3 |
| 3 | 2026-01-15 | Sofa delivery / order S-15 | -60000 | journaled | journals/2026-01/2026-01-15-sofa.md | L4-L5 |
| 4 | 2026-01-19 | Synthetic Rail | -8000 | journaled | journals/2026-01/2026-01-31-card-summary.md | L6 |
| 5 | 2026-01-31 | Closing balance | 0 | ignored | Balance-only observation; no transaction | L7 |

IDs count data records, excluding the header. Locators count actual physical
lines, including the header and quoted line breaks. Ignored opening/closing
rows are balance metadata, not skipped spending. Negative charge amounts in
this note are statement presentation; liability assertions use credit-positive
account direction. This assistant-maintained note is not a native importer or
automatic duplicate guarantee. Preserve completed targets before backfilling.
```

ID はデータレコードの通し番号です。ヘッダー行は数えず、引用符内に改行があっても
1件と数えます。`L` はファイル上の実際の行番号で、ヘッダー行も引用符内の改行も
数えます。そのため、ID 3 は `L4-L5`、ID 4 は `L6` に対応します。IrisBooks 自体の
CSV 読み取りと Web のプレビューも、同じ行範囲で表示します。

メモを再利用する前に、メモの `source_sha` と `iris hash` の結果を照合してください。
明細が再発行された場合は、新しい明細を別のファイルとして保存します。変更された行を
既存の仕訳への参照と比べ、すでに済ませた判断はそのまま残します。`source_sha` を
書き換えるだけでは、照合したことになりません。領収書と口座明細が同じ取引を示して
いるなら、費用も1件です。

### 元資料で過去分を補い、現金も別に照合する

個人用の帳簿で1月31日に確認した現金は10,970円です。

```csv
date,owner_reported_cash
2026-01-31,10970
```

後から見つかった領収書を記帳する前の帳簿上の現金は11,000円です。
`iris reconcile` は実際11,000円・期待10,970円・差額+30円を表示して終了コード1を返します。預金190,000円は一致しています。
理由が分からない間は差額を残してください。30円の購入を作ったり、確認値を書き換えて一致させたりしません。
10月24日に、1月29日付のコピー代の領収書（原本）が見つかり、9,000円の集計には含まれないことを確認したとします。
元資料を保存し、取引日は実際の日付を使います。

```csv
date,merchant,description,amount,currency
2026-01-29,Synthetic Library,Personal copies,30,JPY
```

```yaml
schema_version: 1
date: 2026-01-29
status: posted
lines:
  - {account: Expenses:Copies, debit: 30}
  - {account: Assets:Cash, credit: 30}
attachments:
  - {path: raw/receipts/backfill.csv, type: receipt, locator: L2}
```

発見・確認した日時は `notes/backfill.md` に説明します。取引日やファイル名の日付の代わりには使いません。
下書きを作る前に、すでに記帳されていないか確認してください。
記帳には通常の権限が必要で、締め済みの年度には記帳できません。この例では、2026年度が
締められていないと仮定します。締め済みの年度や過年度の場合は、権限のある人が
再オープンして訂正します。今日の日付の取引に付け替えたり、締め済みの記録を
書き換えたりしないでください。
元資料がそろわない問題は、未解決の質問として残します。

[残高照合](book-format-reference.md#残高照合)の設定に、確認した残高（確認値）を
追加します。それぞれに `scope: posted` と `unit: JPY` を明示します。CSV を置いただけで
確認値が自動的に作られることはありません。事業用の帳簿では、1月27日の現金13,680円と、
1月31日の現金12,580円・預金95,000円・カード債務5,500円を確認値とします。負債は、
貸方残高を正の数で書きます。個人用の帳簿の確認値は次のとおりで、1月の預金・現金・
カード債務と、2月の預金・精算後のカード債務を対象にしています。

残高照合は事業用6件、個人用5件です。

実行確認用の各帳簿には、7仕訳、元の預金・カード明細、ハッシュで対応付けたパースメモ、独立した現金確認、詳しさの方針、追記の経緯を含めています。
事業用の費用は1,320円＋3,300円＋2,200円＋1,100円、個人用は60,000円＋20,000円＋9,000円＋30円です。
預金の一致だけでは個人用の現金差額を見落とします。預金・現金と費用総額が一致していても、ソファの分類と元資料を個別に残した証明にはなりません。
合計額とともに、選んだ詳しさが保たれているかも確認します。

## iris のバージョンを確認して更新する

```bash
iris update --check --json     # 使用中のバージョン・最新版・実行ファイルの場所
iris update                   # 検証してから実行ファイルを置き換える
```

更新確認は、指定したときだけ公開サーバーに問い合わせます。ログインは不要です。
帳簿の操作は引き続きオフラインで使えます。確認に失敗した場合、最新版かどうかは
不明です。開発版・リリース候補は `development` と表示され、自動では置き換えません。
公開版より新しいバージョンを古いものに戻すこともありません。

更新後は帳簿のフォルダで `iris onboard` を実行して AI 向けの案内を更新し、
IrisBooks の MCP サーバーを再起動します。AI に `check_update` を呼び出してもらい、
サーバーが使うバージョンを確認してください。結果には実行ファイルの場所と、
PATH が別のファイルを指している場合の案内も表示されます。

`.mcpb` 拡張には別の実行ファイルが含まれます。確認結果のリンクから対応する
バンドルを入手し、同じ親フォルダを指定してクライアントの拡張設定から入れ直し、
再起動してください。1つの帳簿を指定する旧版から更新する場合は、その帳簿の
親フォルダを新しい設定で選びます。CLI の更新だけでは拡張は更新されません。Windows で実行ファイルが
使用中のため置き換えられない場合は、IrisBooks の MCP サーバーを停止して再実行します。

`iris update` がない古い版は、[インストーラー](getting-started.md)を再実行して更新し、
続けて `iris onboard` を実行します。AI が更新をインストールする前には、ユーザーの
許可が必要です。すでに更新を依頼されている場合は、再確認は不要です。

## オンラインの案内と任意のダウンロード

`iris` には英語のマニュアルが同梱されていて、ログインもネット接続もなしで読めます。

| コマンド | 表示するもの |
| --- | --- |
| `iris docs` | 同梱資料のトピックの一覧 |
| `iris docs <topic>` | そのトピックの節と語数の一覧 |
| `iris docs <topic> --section <id>` | 指定した節 |
| `iris docs <topic> --full` | 章の全文 |

ローカル MCP の `read_docs` も、`topic`・`section`・`full` で同じ内容を返します。
帳簿の指定は要りません。AI は、帳簿の `AGENTS.md`、作業の現状、関係する質問や過去の
判断を先に確認し、そのうえで、コマンドのヘルプやツールの入力形式とあわせてこの資料を
使います。

AI に導入を頼むときは[開始ガイド](https://irisbooks.io/start/)を渡します。現在の
クラウド認証の手順は[クラウド接続](https://irisbooks.io/start/cloud/)にあります。
同梱資料を読めない古いツールでは、[索引](https://irisbooks.io/llms.txt)を使えます。
[AI 向け全マニュアル](https://irisbooks.io/llms-full.txt)は、必要なときだけ参照する
資料です。

マニュアルの Markdown を手元に保存する場合は、帳簿の外に置き、取得元の URL と
リリースタグを控えておきます。取得元は
`https://raw.githubusercontent.com/irisbooks/iris/<release-tag>/docs/llm.md` です。
`<release-tag>` は、できれば `iris --version` が表示するバージョンに合わせます。読むときは、
必要な節だけを検索します。その帳簿に適用されるルールは、帳簿で選択しているオーバーレイで
確認してください。資料に書かれているからといって、その操作が許可されたことには
なりません。

## やってはいけないこと

次のルールが帳簿の信頼性を保ちます（AI もこれに従います）。

- 記帳済の仕訳をまとめて書き換えない。何をどう直したかが追えなくなります。
  訂正は、訂正の仕訳を新しく作って行います。
- `compiled/` を手で編集しない。再生成できる出力なので、再生成すると編集は
  上書きされます。
- 仕訳の中だけで新しい科目を使わない。勘定科目表にない科目は `iris validate` が
  エラーにします。先に勘定科目表へ追加します。

[CLI コマンドリファレンス](cli-reference.md)。

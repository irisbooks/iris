# 日本の税務・コンプライアンス

このページでは、日本で税務申告する際の記帳について説明します。
訂正・削除の履歴や検索といった記録まわりの機能、
消費税の区分、固定資産の減価償却、そして年度締めです。

> **IrisBooks の役割分担。** エンジンは普遍的で安定した部分 — 複式簿記の計算、
> 明細ごとの区分、集計、データ書き出し — を担います。年ごとに変わり、自治体ごとに
> 異なる*書式*そのものは、IrisBooks が出力したデータに対してあなたの AI が記入し、
> 突き合わせます。つまり「数値は IrisBooks が出し、書式は AI が埋め、IrisBooks が
> 整合を確認する」。これは意図的な設計です。

## 履歴・検索・記録のつながり

帳簿の記録をあとから確かめられるよう、IrisBooks には次の4つの機能があります。
あなた自身も、税理士や監査人も使えます。

| 機能 | できること | 使う場所 |
| --- | --- | --- |
| **訂正・削除の履歴** | すべてのファイルへの変更を、削除も含めてサーバーが記録します — 誰が・いつ変更したか、変更前はどうだったか | `iris api history`、Web アプリの**アクティビティ**タイムラインと仕訳ごとの**履歴**パネル（クラウド） |
| **検索** | 日付・金額・取引先を自由に組み合わせて仕訳を探せます。ステータス・勘定科目・タグでも絞り込めます | `iris search`、Web アプリ**仕訳**ページの絞り込み |
| **元帳 ↔ 仕訳** | 元帳の各行に、もとになった仕訳ファイルが示されます | `iris report ledger`、Web アプリ**勘定科目**の元帳 |
| **仕訳 ↔ 元資料** | 各仕訳は領収書・請求書・明細などの元資料を参照していて、そのつながりを双方向にたどれます | `iris references <path>`、Web アプリ元資料ブラウザの**引用元**パネル |

元帳と仕訳のつながりは、個別の機能ではなく設計から生まれています。原本は仕訳
ファイルだけで、総勘定元帳・試算表・決算書は必要なときにそこから計算します。
別の帳簿へ写しを作らないので、両者が食い違うことはありません。

検索と2種類のつながりは、すべてオフラインで使えます。訂正・削除の履歴はサーバーが
記録するので、クラウドに同期している帳簿にしかありません。**ローカルのみの帳簿には、
サーバー側の訂正・削除の履歴がありません。** ローカルの git 履歴は手元の
パソコンにあり、書き換えもできるため、その代わりになる独立した記録ではありません。

帳簿を削除すると、サーバー上の記録もなくなります。30日間の猶予の後、訂正・削除の
履歴を含め、その帳簿のサーバー上のデータはすべて完全に消去されます。紙の帳簿と
同じく、法定保存期間（7年、法人の一部ケースでは最長10年）にわたって帳簿を保存する
義務はあなた自身にあります。帳簿を削除する前に、帳簿フォルダーと、その
`iris api history --all --json` の記録を手元に保存してください
（[監査人への引き渡し](#監査人への引き渡し)を参照）。

> **年度の締め**（seal）は年度の仕訳と会計計算に関わるファイルをロックします。
> 再オープンまで対象ファイルの変更は拒否され、再オープン後の変更にはこの履歴で
> 締め後の印が付きます。`raw/` と `notes/` は引き続き変更できます。[年度締め](#年度締め)を参照。

> **認証は受けていません。** IrisBooks は JIIMA 認証などの認証を受けておらず、
> IrisBooks で付けた帳簿が優良電子帳簿の要件を満たすとも主張していません。
> あなたの帳簿が要件に該当するか、税務署へあらかじめ届出を出すかどうかは、
> あなたと税理士で判断してください。

## 消費税

そもそも消費税を管理するかどうかは、事業者区分によります。`config/book.yaml` で
一度だけ宣言します。

```yaml
consumption_tax:
  status: taxable          # taxable（課税事業者）| exempt（免税事業者）
  accounting: tax_included # tax_included（税込）| tax_excluded（税抜）
  method: general          # general（本則）| simplified（簡易課税）
  business_class: 5        # 1..6、簡易課税のみ
```

- **免税事業者**（`consumption_tax` ブロック無し、または `status: exempt`）は、
  税込金額を通常の売上 / 経費として記録し、税の内訳は持たず、消費税申告もしません。
  この節の残りは読み飛ばして構いません。
- **課税事業者**は、年間を通じて関連する各**明細**に `tax` ブロックで区分を付けます。
  年度末に区分・税率ごとの合計が消費税申告書を駆動し、IrisBooks が集計した数値に
  対して AI が書式を埋めます。

### 明細を区分する

消費税のかかる明細に `tax` ブロックを追加します。

```yaml
lines:
  - account: 収益:売上
    credit: 100000
    tax:
      category: taxable_sale   # 課税売上
      rate: "10"               # 標準10%
  - account: 費用:消耗品費
    debit: 5000
    tax:
      category: taxable_purchase
      rate: "10"
      invoice: true            # 適格請求書を保有している
```

**区分**（`category`）:

| トークン | 税区分 | 税率を持つか |
| --- | --- | --- |
| `taxable_sale` | 課税売上 | はい（正の率） |
| `taxable_purchase` | 課税仕入 | はい（正の率） |
| `exempt_sale` | 非課税売上 | なし |
| `exempt_purchase` | 非課税仕入 | なし |
| `export_sale` | 免税売上（輸出） | `0`（または省略） |
| `out_of_scope` | 不課税 / 対象外 | なし |
| `securities_sale` | 有価証券譲渡 | なし |

**税率トークン**（`rate`）: `"10"`（標準）、`"8r"`（軽減税率8%）、`"8o"`（旧/
経過措置8%、`8r` とは別）、`"5"`、`"3"`（旧税率）、`"0"`（輸出）。

**インボイスフラグ**（`invoice`）: 仕入側の明細で、適格請求書等保存方式
（インボイス制度、2023年10月〜）のもとで適格請求書を保有しているかどうか。

**簡易課税**（`method: simplified`）: 各課税売上の明細には事業区分
（`business_class`、第1〜6種）が必要です。帳簿レベルの `business_class` を既定値と
し、明細ごとに上書きできます。

`iris validate` はこれらの整合をチェックします — 区分が既知か、税率が区分に合うか
（例：`taxable_sale` には正の率が必要、`export_sale` は0%）、簡易課税の売上に有効な
事業区分があるか。詳しい区分判定ルール（区分判定、簡易課税 事業区分、インボイス
経過措置）は税法であってプロダクトの仕様ではありません — AI が区分時に国税庁の
現行ページで対象の区分と期間を確認します。製品への入力は選択中のオーバーレイの
項目定義やガイドを調べ、法令上の扱いは必要な一次資料で確認します。
そのためだけに AI 向け全マニュアルを読む必要はありません。変わりうるルールの凍結コピーを IrisBooks は同梱しません
— iris は検証者であって、立法者ではありません。

### 年度末の集計

申告書に載せる合計は、エンジンが出します。明細を手で足し直す必要はありません。

```bash
iris report sum --by tax.category,tax.rate --from 2026-01-01 --to 2026-12-31
```

記帳済みの全明細を税区分ごとにグループ化して正確に合計します（インボイスの
区分けは `tax.invoice` を、簡易課税は `tax.business_class` を追加）。なお課税期間は
個人は暦年、法人は事業年度（`--year`）です。

日本オーバーレイはさらに一歩進めて、この集計を申告書の形に組み合わせる 2 つの
**レシピ**を持っています。`jp-tax-filing.shouhizei-general`（本則課税 — 税率別の課税売上・
課税仕入、パッケージの日付別定義による経過措置計算、課税売上割合、
差引税額、百円未満切捨ての納付税額）と `jp-tax-filing.shouhizei-simplified`（簡易課税 —
事業区分別の売上税額と、渡したみなし仕入率による仕入税額控除）です。
`iris overlay recipe jp-tax-filing.shouhizei-general --set from=2026-01-01 --set
to=2026-12-31 --set scope_confirmed=true --apply --out
filings/jp-tax-filing.shouhizei-general.md` で集計値が `filings/` に根拠付きで記録され、
以後 `iris validate` が仕訳に対してレシピを再計算します。申告後に訂正を記帳すると、
レシピを再実行するまでエラーになります。AI は記録された集計値から様式に転記
します。役割分担はここでも同じ：**IrisBooks が集計し、AI が申告する。**

`jp-tax-classification` と `jp-tax-filing` を一緒に選択します。
ガイドの対応範囲を確認してから `scope_confirmed=true` を渡してください。
結果は計算補助であり、完成した申告書ではありません。

**税抜経理**の帳簿（`accounting: tax_excluded`）では、`iris validate` が
`tax.amount` のない区分済み明細について、明細に含まれる消費税額をヒントとして
提案します。`iris validate --apply` で記録され、AI はその額を仮払消費税 / 仮受消費税に
計上します — 計算は iris、仕訳は AI です。

## 固定資産と減価償却

各償却資産を `assets/YYYY/<name>.md` のファイルとして記述します。

```yaml
---
name: "MacBook Pro 16"
acquisition_date: 2026-04-15
acquisition_cost: 480000
salvage_value: 1
useful_life_months: 48        # 耐用年数4年 × 12
method: straight_line         # straight_line | declining_balance | expensed
asset_account: "資産:工具器具備品"
depreciation_expense_account: "費用:減価償却費"
accumulated_depreciation_account: "資産:減価償却累計額"
---
```

- **`useful_life_months`** は、`straight_line` と `declining_balance` では
  耐用年数省令の表から取ります。AI が国税庁の現行
  ページ（耐用年数省令 別表第一・第二。定率法は別表第十の償却率）で正しい耐用
  年数を調べ、確定した数値をファイルに記録します — 帳簿が自らの根拠を持ち、
  「どの改定時点の表か」は ファイルの git 履歴が答えます。
- **方法**: `straight_line`（定額法）、`declining_balance`（定率法）、
  `expensed`（即時償却）。定額法と即時償却は iris が計算します。定率法は AI が
  償却表をファイルに記録します（下記）。改定償却率への切替は日本固有の規定で、
  iris はどの国の規定も持たない設計だからです。
- **即時償却**（`expensed`。少額減価償却資産の特例 `toku_rei: shoutoku_300k`
  など）: 購入は他の資産と同じく資産の科目に計上してください。
  `iris asset depreciate` が取得月に全額を償却します。`useful_life_months` は
  省略するか `0` にし、`schedule` も省略してください。正の耐用月数や記録済みの
  償却表があるとエラーになります。これでその資産が年度の
  償却額（`period_dep`）に入り、青色申告決算書の減価償却費の計算欄や別表16(7) に
  載ります。

### 定率法 — 償却表を記録する

定率法は、その年の償却額が償却保証額（取得価額 × 保証率）を下回るまで償却率で
償却し、以降は改定取得価額 × 改定償却率の定額に切り替えて耐用年数まで償却します。
切替・端数処理・前後半の連結は日本オーバーレイの `jp-declining-balance.teiritsu` レシピに組み込まれて
います。AI は入力を渡すだけで、あとは iris が行います。

1. 国税庁サイトの別表第十で、その耐用年数の償却率・保証率・改定償却率を調べる
   （2012年4月以降の取得は 200% の表、2007年4月〜2012年3月は 250% の表。資産は
   取得時の表を使い続けます）。
2. その率と取得価額、耐用年数（年）、最初の期末月を渡してレシピを実行する —
   `iris overlay recipe jp-declining-balance.teiritsu --set full_year_confirmed=true --set cost=1000000 --set life=8
   --set rate=0.250 --set guarantee=0.07909 --set revised=0.334
   --set start=2027-03 --apply --out assets/2026/lathe.md`、または MCP の
   `run_recipe(recipe="jp-declining-balance.teiritsu", params={...}, apply=true, out="assets/2026/lathe.md")`（親モードは `book` も指定）。表が `schedule:` に、根拠が `schedule_source:` に
   書き込まれます。

取得価額 100 万円・耐用年数 8 年（償却率 0.250、保証率 0.07909、改定償却率
0.334）、3 月決算ならこうなります。

```yaml
method: declining_balance
useful_life_months: 96
schedule:
  - period: 2027-03
    amount: 250000     # 償却率による年
  - period: 2028-03
    amount: 187500
  - period: 2029-03
    amount: 140625
  - period: 2030-03
    amount: 105468
  - period: 2031-03
    amount: 79101      # 償却保証額 79,090 をまだ上回る
  - period: 2032-03
    amount: 79260      # 切替後: 改定取得価額 237,306 × 0.334
  - period: 2033-03
    amount: 79260
  - period: 2034-03
    amount: 78785      # 備忘価額 1 円で終わる
schedule_source:       # レシピが書く: 入力。再計算と税理士の確認のために
  overlay: jp-declining-balance@2026.10.1
  recipe: jp-declining-balance.teiritsu
  bindings: 5
  primitives: {declining_table: 2, flat_table: 2}
  params: {full_year_confirmed: true, cost: 1000000, life: 8, rate: 0.250, guarantee: 0.07909, revised: 0.334, start: 2027-03, salvage: 1}
```

iris は合計が取得価額 − 備忘価額と一致するか、表の形が正しいかを検査し — 入力が
ファイルにあるので — `iris validate` のたびに**レシピを再計算**し、行が違えば
ファイルを受け付けません。合計だけでなく、切替の年の誤りも捕まります。率は
そのまま残るので、税理士が別表第十と突き合わせられます。

続いて償却を実行します。

```bash
iris asset schedule --year 2026        # 各資産の償却計画
iris asset depreciate --year 2026      # 年次: 年度合計の仕訳を期末日付で資産ごとに生成
iris asset depreciate --month 2026-05  # 月次: その月の仕訳を生成
iris export assets --year 2026         # 資産別スケジュールを CSV で
```

個人事業主や小規模法人の多くは、減価償却を年 1 回の決算整理仕訳として計上します —
それが `--year` です。資産ごとに年度合計の提案仕訳を期末日付で書き出します
（期中取得の月割も自動）。月次で締める帳簿は `--month` を使います。方式は会計
年度ごとにどちらか一方を選びます — 混在は二重計上になるためコマンドが拒否します。
いずれの場合も `iris asset depreciate` は提案仕訳を書き出すので、ほかの仕訳と
同様にレビューして記帳します。

申告書類そのもの — 固定資産台帳、償却資産税 申告書（市町村別）、別表16 — は、
AI が資産ファイルとエンジンの年度数値（`iris export assets --year` /
`iris asset schedule --year`）、そして当年度の公式様式（国税庁または各市町村の
公表レイアウト）から作成し、帳簿の `compiled/jp/<様式>/` に書き出します。
様式は毎年変わるので、AI はその年度の様式をその都度取得して作業します。

## 年度締め

1つの帳簿は1会計年度分です。年度締めには会計面とコンプライアンス面があり、
どちらも締める年度の帳簿で実行します：

```bash
iris yearend                                      # FY2026 の帳簿を期首残高仕訳付きで作成
# …決算整理と申告は、ここ FY2025 の帳簿で行う…
iris yearend                                      # 遅れた訂正のあと: FY2026 の期首残高を更新
iris seal --dry-run 2025                          # 何が締められるか確認（クラウド）
iris seal 2025                                    # 年度を締める（クラウド）
```

- **翌年度の帳簿（`iris yearend`）。** この帳簿と同じ階層に FY2026 の帳簿を
  コピーとして作ります。設定・勘定科目表・ガイド・ノート、まだ保有している
  固定資産に加えて、今年度の期末残高から計算した**期首残高**仕訳が入るので、
  新年度は整合した自己完結の状態で始まります。2026 年の日付ですでに記録した
  仕訳は新しい帳簿へ移ります。クラウドの帳簿なら、同じ手順で新しい帳簿の
  クラウド側も作られ（同じメンバーがアクセスでき、受信アドレスも新しい帳簿へ
  移ります）、両方の帳簿が同期されます。新年度が始まったらすぐに実行して
  構いません。決算整理と申告は引き続き古い帳簿で行い、再実行のたびに新しい
  帳簿の期首残高が更新されます。
  [iris yearend](cli-reference.md#iris-yearend) を参照。
- **締め。** 会計年度を「誰が・いつ締めたか」とともに締め済みにマークし、
  年度内の仕訳と `config/`・`assets/`・`filings/`・`compiled/` を
  **ロック**します。再オープンまで対象ファイルの変更をサーバーが拒否します。
  `raw/` と `notes/` は引き続き変更できます。年度内の仕訳は `closed`
  として表示されます。
- **削除されるものはありません。** 締めても再オープンしてもファイルは削除
  されません。年度のファイルは、過去のすべての版とともに作業ツリーと
  サーバーにそのまま残ります。

同期して締める前に、ローカルで `iris validate` を実行してください。
Overlay のルール検証と保存済みレシピの再計算は、帳簿内に保持した定義を使って
ローカルで行います。クラウドはこれらを実行せず、検証済みであるとも保証しません。
`config/balance-assertions.yaml` がある場合、`--dry-run` は同期済みデータに対する
共通処理の結果として、帳簿残高・確認残高・差額、対象範囲、証拠ファイルの確認状況を
表示します。残高や証拠の不一致が残ると締められません。元の記録や残高確認の設定を
ローカルで修正し、証拠を確認してから同期し、プレビューをやり直してください。
未同期の変更は対象外です。同期後も元文書の参照データの不足・古さを報告する場合は、
サーバー側での再構築が必要です。[Discordコミュニティ](https://discord.gg/wZDsv9gyb9)で相談してください。

締め済み年度を修正したいときは、その年度の帳簿で再オープンして編集し、
再同期してから再度締めます。

```bash
iris reopen 2025      # 締めのロックを解除（年度のファイルは作業ツリーにそのまま）
# …訂正する…
iris sync             # push。サーバーはこれらを締め後の編集としてフラグ
iris yearend          # FY2026 の帳簿の期首残高を更新（2026 がまだ開いている場合）
iris seal 2025        # 年度を再度締める（古い締めを引き継ぐ）
```

翌期*も*すでに締め済みの場合、`iris yearend` はその期首残高仕訳を申告済みの
まま凍結し、その旨を報告します — 差額は新しい帳簿で当期の訂正仕訳
（前期損益修正）として計上するか、翌期も再オープンしてください。

締め / 再オープンは Web アプリからも行えます。
帳簿の**年度の締め**画面にその帳簿の会計年度と締め状態が並び、同じ
プレビュー → 締め → 再オープンの流れを操作できます —
[Web アプリを使う](web-app.md#年度の締め)を参照。翌年度の帳簿を作る
`iris yearend` だけは、パソコン上にフォルダを作るため CLI 専用です。

### 監査人への引き渡し

監査人・税理士・税務署に求められるものは、すでに帳簿の中にあります。

- **帳簿。** 帳簿フォルダーそのもの（プレーンな Markdown と YAML）。会計年度
  単位の CSV なら `iris export --year 2025`（クラウドの帳簿からは
  `iris api export --year 2025 <book-id>`）で書き出せます。
- **訂正・削除の履歴**をファイルで：

  ```bash
  iris api history --all --json <book-id> > history-2025.json
  ```

  帳簿がその年度そのものなので、その年度の記録に対するすべての変更 —
  何が、誰によって、いつ変わったか — を、年度を締めた後の訂正
  （`post_seal_period` の印付き）も含めて一覧にします。[iris api history](cli-reference.md#iris-api-balance-holdings-history)
  を参照。
- **アクセス。** 税理士を帳簿に招待すれば、仕訳ごとに履歴を見てもらえます —
  [共同作業と役割](web-app.md#共同作業と役割)を参照。

# 記録の履歴と年度締め

このページでは、帳簿の記録をあとから確かめるための機能（訂正・削除の履歴、検索、
記録のつながり）、帳簿から申告書を作る流れ、年度の締めと引き渡しについて説明します。

## 履歴・検索・記録のつながり

帳簿の記録をあとから確かめられるよう、IrisBooks には次の4つの機能があります。
あなた自身も、税理士や監査人も使えます。

| 機能 | できること | 使う場所 |
| --- | --- | --- |
| **訂正・削除の履歴** | すべてのファイルへの変更を、削除も含めてサーバーが記録します — 誰が・いつ変更したか、変更前はどうだったか | `iris api history`、Web アプリの**アクティビティ**タイムラインと仕訳ごとの**履歴**パネル（クラウド） |
| **検索** | 日付・金額・取引先を自由に組み合わせて仕訳を探せます。ステータス・勘定科目・タグでも絞り込めます | `iris search`、Web アプリ**仕訳**ページの絞り込み |
| **元帳 ↔ 仕訳** | 元帳の各行に、もとになった仕訳ファイルが示されます | `iris report ledger`、Web アプリ**勘定科目**の元帳 |
| **仕訳 ↔ 元資料** | 各仕訳は領収書・請求書・明細などの元資料を参照していて、そのつながりを双方向にたどれます | `iris references <path>`、Web アプリ元資料ブラウザの**引用元**パネル |

元帳と仕訳のつながりは、個別の機能ではなく設計から生まれています。原本は仕訳
ファイルだけで、総勘定元帳・試算表・決算書は必要なときにそこから計算します。
別の帳簿へ写しを作らないので、両者が食い違うことはありません。

検索と2種類のつながりは、すべてオフラインで使えます。訂正・削除の履歴はサーバーが
記録するので、クラウドに同期している帳簿にしかありません。**ローカルのみの帳簿には、
サーバー側の訂正・削除の履歴がありません。** ローカルの git 履歴は、
その代わりになりません。手元のパソコンにあり、書き換えもできるため、独立した記録とは
言えないからです。

帳簿を削除すると、サーバー上の記録もなくなります。30日間の猶予の後、訂正・削除の
履歴を含め、その帳簿のサーバー上のデータはすべて完全に消去されます。紙の帳簿と
同じく、税法が定める保存期間にわたって帳簿を保存する義務はあなた自身にあります。
帳簿を削除する前に、帳簿フォルダと、その `iris api history --all --json` の
記録を手元に保存してください（[監査人への引き渡し](#監査人への引き渡し)を参照）。

> **年度の締め**（seal）は年度の仕訳と会計計算に関わるファイルをロックします。
> 再オープンまで対象ファイルの変更は拒否され、再オープン後の変更にはこの履歴で
> 締め後の印が付きます。`raw/` と `notes/` は引き続き変更できます。[年度締め](#年度締め)を参照。

> **認証は受けていません。** IrisBooks は第三者の認証を受けておらず、IrisBooks で
> 付けた帳簿がいずれかの国・地域の電子帳簿の基準を満たすとも主張していません。
> あなたの帳簿が基準に該当するか、税務当局への届出が必要かどうかは、あなたと
> 税理士で判断してください。

## 申告と地域のルール

エンジンが担うのは、どの地域でも変わらない安定した部分です。複式簿記の計算、
明細ごとに記録する項目、集計、データの書き出しを扱います。税区分、償却方法、
申告に必要な数値といった地域ごとのルールは、帳簿で選択した[オーバーレイ](https://irisbooks.io/docs/ja/overlays/)
だけが提供します。あなたの地域向けのパッケージがある場合は、オーバーレイの地域ガイドが、
どのパッケージを選ぶか、パッケージに含まれない作業は何かを説明しています。
地域向けのパッケージがない帳簿には、共通の検証だけが適用されます。

計算資料のレシピは、計算結果を、計算条件と一緒に `filings/` に記録します。
`iris validate` はこのレシピを再計算します。そのため、申告のあとに訂正を記帳すると、
レシピを実行し直すまでエラーが表示されます。

申告書そのものは、あなたの AI が作成します。様式が毎年変わり、地域によっても異なる
ためです。AI は、エンジンの数値、記録した計算資料、最新の公式様式をもとに申告書を作り、
帳簿の `compiled/<地域>/<様式>/` に保存します。つまり、集計は IrisBooks、申告書の
作成は AI、提出はあなたの役割です。

## 年度締め

1つの帳簿は1会計年度分です。年度末にすることは2つあります。翌年度の帳簿を作って残高を引き継ぐこと
（`iris yearend`）と、終わった年度をロックすること（`iris seal`）です。どちらも、
締める年度の帳簿の中で実行します。

```bash
iris yearend                                      # FY2026 の帳簿を期首残高仕訳付きで作成
# …決算整理と申告は、ここ FY2025 の帳簿で行う…
iris yearend                                      # 遅れた訂正のあと: FY2026 の期首残高を更新
iris seal --dry-run 2025                          # 何が締められるか確認（クラウド）
iris seal 2025                                    # 年度を締める（クラウド）
```

- **翌年度の帳簿（`iris yearend`）。** この帳簿と同じ階層に FY2026 の帳簿を
  コピーとして作ります。設定・勘定科目表・ガイド・ノート、まだ保有している
  固定資産に加えて、今年度の期末残高から計算した**期首残高**仕訳が入るので、
  新年度は整合した自己完結の状態で始まります。2026 年の日付ですでに記録した
  仕訳は新しい帳簿へ移ります。クラウドの帳簿なら、同じ手順で新しい帳簿の
  クラウド側も作られ（同じメンバーがアクセスでき、受信アドレスも新しい帳簿へ
  移ります）、両方の帳簿が同期されます。新年度が始まったらすぐに実行して
  構いません。決算整理と申告は引き続き古い帳簿で行い、再実行のたびに新しい
  帳簿の期首残高が更新されます。
  [iris yearend](cli-reference.md#iris-yearend) を参照。
- **締め。** 会計年度を「誰が・いつ締めたか」とともに締め済みにマークし、
  年度内の仕訳と `config/`・`assets/`・`filings/`・`compiled/` を
  **ロック**します。再オープンまで対象ファイルの変更をサーバーが拒否します。
  `raw/` と `notes/` は引き続き変更できます。年度内の仕訳は `closed`
  として表示されます。
- **削除されるものはありません。** 締めても再オープンしてもファイルは削除
  されません。年度のファイルは、過去のすべての版とともに作業ツリーと
  サーバーにそのまま残ります。

同期して締める前に、ローカルで `iris validate` を実行してください。
オーバーレイのルール検証と保存済みレシピの再計算は、帳簿内に保持した定義を使って
ローカルで行います。クラウドはこれらを実行せず、検証済みであるとも保証しません。
`config/balance-assertions.yaml`（明細などで確かめた残高の記録）がある場合、`--dry-run` は
残高照合の結果も表示します。照合の対象は同期済みのデータで、帳簿上の残高・確かめた
残高・差額、対象範囲、根拠にした資料の確認状況が出ます。残高か資料に不一致が残って
いると、締められません。元の記録や残高の記録をローカルで修正し、資料を確認してから
同期し、プレビューをやり直してください。まだ同期していない変更は、このプレビューの
対象外です。同期したあとも、元資料についてのサーバー側のデータが不足している、または
古いと報告される場合は、サーバー側での再構築が必要です。
[Discordコミュニティ](https://discord.gg/wZDsv9gyb9)で相談してください。

締め済み年度を修正したいときは、その年度の帳簿で再オープンして編集し、
再同期してから再度締めます。

```bash
iris reopen 2025      # 締めのロックを解除（年度のファイルは作業ツリーにそのまま）
# …訂正する…
iris sync             # 送信。サーバーはこれらを締め後の編集として記録
iris yearend          # FY2026 の帳簿の期首残高を更新（2026 がまだ開いている場合）
iris seal 2025        # 年度を再度締める（新しい締めが古い締めに代わる）
```

翌年度*も*すでに締め済みの場合、`iris yearend` は翌年度の期首残高仕訳を更新しません。
申告済みの内容のまま残し、更新しなかったことを報告します。この場合は、次のどちらかで
対応してください。

- 差額を、新しい帳簿で当期の訂正仕訳（前期損益修正）として計上する。
- 翌年度も再オープンする。

締め / 再オープンは Web アプリからも行えます。
帳簿の**年度の締め**画面にその帳簿の会計年度と締め状態が並び、同じ
プレビュー → 締め → 再オープンの流れを操作できます
（[Web アプリを使う](web-app.md#年度の締め)を参照）。翌年度の帳簿を作る
`iris yearend` だけは、パソコン上にフォルダを作るため CLI 専用です。

### 監査人への引き渡し

監査人・税理士・税務当局から求められる資料は、次の方法で用意できます。

- **帳簿。** 帳簿フォルダそのもの（プレーンな Markdown と YAML）。会計年度
  単位の CSV なら `iris export --year 2025`（クラウドの帳簿からは
  `iris api export --year 2025 <book-id>`）で書き出せます。
- **訂正・削除の履歴**をファイルで：

  ```bash
  iris api history --all --json <book-id> > history-2025.json
  ```

  1つの帳簿が1会計年度分なので、このファイルは、その年度の記録に対するすべての
  変更（何が、誰によって、いつ変わったか）の一覧になります。年度を締めた後の訂正も、
  `post_seal_period` の印付きで含まれます。
  [iris api history](cli-reference.md#iris-api-balance-holdings-history) を参照。
- **アクセス。** 税理士を帳簿に招待すれば、仕訳ごとに履歴を見てもらえます —
  [共同作業と役割](web-app.md#共同作業と役割)を参照。

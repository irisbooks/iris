# トラブルシューティング

よくある状況と解決法です。迷ったらまず `iris validate` を実行してください。何が
おかしいかを知る一番速い方法です。

## `iris validate` がエラーを出す

`iris validate` は全ファイルをチェックし、問題点を表示します。よくある原因:

- **貸借不一致** — 借方と貸方が一致しない。合計が等しくなるよう金額を直します。
- **未知の科目** — 仕訳が `config/chart-of-accounts.yaml` に無い科目を参照して
  いる。勘定科目表に科目を追加するか、既存の科目のエイリアスを使います。
  勘定科目表にない科目パスは、仕訳の中だけでは使えません。
- **日付の不一致** — `date:` フィールドがファイル名の `YYYY-MM-DD` 接頭辞と一致
  しない。両者を合わせます。
- **不正なステータス** — `status` に書けるのは `draft` か `posted` だけです。
- **YAML が解析できない** — たいていは、ファイル先頭の YAML 部分（フロントマター）の
  インデントか、余分なコロンが原因です。エラーにファイル名が出ます。
- **オーバーレイのルール** — 帳簿で選択したパッケージの検証です。たとえば、
  パッケージが受け付けない値の項目。メッセージにルール名が表示されます。項目の
  説明は[オーバーレイ](https://irisbooks.io/docs/ja/overlays/)のパッケージのページにあります。

直して再実行します。このループは AI アシスタントに任せられます。

## 「記帳したのにレポートに出ない」

レポートに載るのは**記帳済**の仕訳だけです。`iris balance`・損益計算書・貸借
対照表に取引が出てこないなら、ほぼ確実にステータスがまだ `draft` のままです。
次のコマンドで記帳します。

```bash
iris post journals/2026-05/2026-05-04-example-com-01.md
```

あるいは `status:` フィールドを `posted` に書き換えて、再検証します。

## 「iris: command not found」

シェルが `PATH` の中に `iris` を見つけられていません。次の順に確かめてください。

1. コマンドを実行しているのがどのマシン（または VM）かを確認します。`iris` を
   入れたのとは別の環境かもしれません。
2. インストールした直後なら、新しいターミナルを開きます。
3. それでも見つからなければ、インストーラーが表示した実行ファイルの絶対パスを
   使って `iris version` を実行します。

`iris` が本当に入っていない場合だけ、[はじめに](getting-started.md)の手順で
インストールします。帳簿のフォルダに `iris` の実行ファイルは入っていません。
サンドボックスの中で動く AI は、ホスト側の MCP サーバーに接続できれば、そちらを
使えます。その場合は `check_update` でバージョンを確かめてください。

## 同期の拒否（needs-attention）

`iris validate` が調べるのは手元の*ファイル*です。同期でファイルを送るときには、
サーバーがさらに別のチェックを行い、次のような場合に受け取りを拒否します。

- 仕訳が使っている科目が、サーバー側の勘定科目表にない。
- 仕訳が参照している `raw/` のファイルが、まだアップロードされていない。
- ファイルをサーバーが記録として読めない、または許可されていない変更である。

拒否されたファイルがあると、`iris validate` の末尾に「N file(s) blocked in the
sync queue」のような注記が出ることがあります。ファイルは壊れていません。
拒否されたのは、サーバーへの*送信*です。

まず、拒否の理由を確認します。

```bash
iris sync issues list      # 項目ごとの理由を表示
```

次に原因を直します。たいていは次のどちらかです。

- 不足している科目を `config/chart-of-accounts.yaml` に追加する。
- 参照している `raw/...` の資料がフォルダにあり、同期されていることを確認する。

**拒否された仕訳そのものを直した場合は、これで終わりです。** `iris` は、拒否された
ファイルを内容が変わるまで送り直しません。内容が変わったので、次の同期で自動的に
送られます。

直したのが*別の*ファイルの場合（例：数日前に勘定科目表を直し、仕訳には触って
いない）は、仕訳の内容が変わっていないので、送り直すよう指示します。

```bash
iris sync issues retry            # 拒否されたファイルをすべて送り直す
iris sync issues retry --path <relpath>   # 1ファイルのみ
```

## 容量の上限（`CAPACITY_EXCEEDED`）

一時的な失敗ではなく、処理の上限に達しています。同じリクエストを繰り返しても
解消しません。エラーに示された処理と上限を確認してください。レポートや検索では、
可能なら期間や条件を絞ります。勘定科目表の置き換えは、1回の更新で1,500科目以内に
収める必要があります。仕訳が参照している科目は削除しないでください。安全に処理を
小さくできない場合は、[Discordコミュニティ](https://discord.gg/wZDsv9gyb9)で相談してください。

## 同期のコンフリクト

あなたと別の人が（または、あなたが別の端末で）同じファイルを変更すると、同期で
変更がぶつかることがあります。これがコンフリクトです。このとき**元のファイル名には
サーバー側の版が入り**、あなたの版は隣に `<file>.conflicted` という名前で保存されます。
`.conflicted` ファイルが1つでも残っている間、`iris sync` は先へ進みません。
そのため、どちらの版も失われません。

```bash
iris conflicts list
```

一覧に出たファイルを1件ずつ解決します。ふつうは**手で統合**します。元のファイルを
開き、`.conflicted` ファイルから必要な部分を取り込みます。終わったら `.conflicted`
ファイルを削除し、もう一度 `iris sync` を実行します。どちらか一方を丸ごと採用する
ときは、次のコマンドを使います。

```bash
iris conflicts resolve <path> --keep mine     # あなたの版を残す（サーバーの版を置き換える）
iris conflicts resolve <path> --keep cloud    # サーバーの版を残す（あなたの版を破棄する）
```

## `iris sync` が終了コード 3 で終わる

終了コード `3` は、この帳簿が**クラウドから切り離されていて**、同じ操作を
繰り返しても同期できないことを表します。原因は次の3種類で、どれに当たるかは
サマリー（`iris sync --json` では `disconnectReason` フィールド）に表示されます。

- **deleted** — オーナーがサーバー上の帳簿を削除しました（Web アプリ →
  帳簿の設定 → 危険な操作）。**ローカルのファイルは無事です。** フォルダからは何も
  削除されず、`iris status` には `Remote: deleted on the server` と表示されます。
  - ローカルで作業を続けるには、`config/book.yaml` の `book_id` をローカル ID に
    戻します。ローカル ID は `iris status` が表示します。
  - クラウドにつなぎ直すには、`iris api books new --no-link` で新しい帳簿を作り、
    `iris api books link --force <id>` でリンクします。フォルダが削除済みの ID を
    指したままなので、`--no-link` を付けない `new` は拒否されます。
- **forbidden** — アクセスが取り消されたか、自分で帳簿から抜けました。認証情報は
  有効ですが、この帳簿への権限がありません。もう一度使うには、帳簿のオーナーに
  再招待を依頼し、Web アプリで招待を承認します。意図して取り消された場合、
  対応は不要です。
- **auth_expired** — セッションが失効しました。`iris api login` でサインインし直し、
  `iris sync` を再実行してください。

## クラウドのコマンドがネットワークエラーを報告する

サーバーへのリクエストが失敗すると、メッセージにはリクエスト、何が起きたか、
再試行で解決する見込みがあるかが表示されます。

```text
iris api login: device authorization request failed: POST https://irisbooks.io/api/cli-auth/device/start: no HTTP response within 45s (timeout; retryable): context deadline exceeded (Client.Timeout exceeded while awaiting headers)
```

括弧の中は失敗の種類と、再試行で成功しうるかどうかです。

- **timeout**、**connect** — 応答が届きませんでした。多くは一時的なネットワークの
  問題なので、同じコマンドをもう一度実行してください。何度も失敗する場合は
  接続を確認してください。
- **dns** — サーバーの名前を解決できませんでした。`not retryable` はその名前が
  存在しないことを表します。メッセージ内のアドレスと DNS の設定を確認して
  ください。
- **tls** — 安全な接続を検証できませんでした。通信を検査するネットワークでよく
  起きます。メッセージ内のアドレスを許可するよう、ネットワークの管理者に依頼
  してください。
- **proxy** — プロキシが失敗したか、アドレスを拒否しました。`not retryable` は
  プロキシがブロックしていることを表すので、プロキシの許可リストにアドレスを
  追加してください。
- **HTTP** とステータス — サーバーが応答しました。`retryable` のステータス
  （408・429・500・502・503・504）は一時的なものなので、少し待って再試行して
  ください。それ以外のステータスは、リクエストの内容を変えない限り、
  再試行しても同じ結果になります。ステータスの後ろに表示される説明を読んでください。

応答がなかったときは、リクエストがどこまで進み、どれだけ経って失敗したかも
表示します（例: `while connecting, after 30.0s`）。名前解決や接続の段階で
止まっている場合はネットワークかプロキシ、応答待ちの段階ならサービス側が
原因の可能性が高いので、少し待ってから再実行してください。

`iris api login --device-complete` が応答を受け取れなかった場合、保留中の
ログインは残るので、同じコマンドをもう一度実行してください。`iris sync --json`
は同じ情報を `errorDetail` フィールドで返します。

## 「締め済みの年度を変えたい」

締め済みの会計年度は**ロック**されています。`iris post` はその年度の仕訳を
拒否します（メッセージ: "FY \<n\> is sealed (closed period) — run
`iris reopen <n>` to amend it, then re-seal"）。サーバーも、年度内の仕訳と
`config/`・`assets/`・`filings/`・`compiled/` の変更を、再オープンするまで
拒否します。`raw/` と `notes/` は変更できます。ローカルのファイルは編集できますが、
ロック対象の変更は同期できません。会計記録を修正するには、まず年度を再オープンします。

```bash
iris reopen 2025      # 締めのロックを解除（ファイルは作業ツリーにそのまま）
# …訂正する…
iris sync
iris seal 2025        # 年度を再度締める
```

サーバーはこの訂正を**締め後の編集**として記録します。アクティビティに表示され、
Web アプリでは「締め後」のバッジが付きます。不具合ではありません。締めた後でも
訂正はでき、その訂正は必ず記録に残る、という仕組みです。締め直すと、新しい締めが
古い締めに代わり、古い締めも履歴に残ります。

**日付を変えると、仕訳は別の年度へ移ります。** そのため、締め済みの年度にある
仕訳の日付を、締めていない年度の日付に変えることも拒否されます。金額が締めた年度から
出ていけば、その年度の合計が変わります。仕訳をその場で編集するのと同じ扱いです。
拒否メッセージに出る年度は、移動先ではなく**締め済みの年度**です。先にその年度を
再オープンしてから、日付を変更してください。

## 「Web アプリと CLI で数値が違う」

ほぼ必ず同期のずれかステータスの違いです。

- `iris diff` で、まだ同期していないローカルの変更を確認し、`iris sync` を実行します。
- Web アプリも CLI と同じく、レポートに載るのは記帳済の仕訳だけです。ローカルで
  見えている下書きは、記帳して同期するまで現れません。
- Web アプリのレポートには、サーバーが数値を最後に計算した時刻が表示されます。
  同期の直後は、数値に反映されるまで少し待ってください。

## `iris view` が開かない、または閉じたと表示される

- **「この画面は閉じられました。もう一度IrisBooksを開いてください。」**
  どのウィンドウからも数分間使われないと、画面は終了します。ウィンドウを閉じた
  後や、パソコンがスリープしていた間などです。もう一度 `iris view` を実行するか、
  ランチャーから IrisBooks を開いてください。
- **専用のウィンドウではなく、ブラウザのタブで開いた。** Chrome も Edge も
  見つかりませんでした。Linux で snap 版の Chromium を使っている場合もタブで
  開きます。使える機能は同じですが、そのブラウザの拡張機能は有効なままです。
- **ランチャーを開いても何も起きない。** ランチャーは、それを追加した `iris` を
  使います。`iris` を別の場所に移した場合は、`iris view --add-launcher` を
  もう一度実行してください。Mac では理由がアラートに表示されます。
- **AI が `iris view` を実行したのに、ウィンドウが出ない。** AI アシスタントが
  VM やコンテナの中で動いている場合、ウィンドウはそちらで開いていて、あなたの
  画面には出ません。ランチャーから IrisBooks を開くか、自分で `iris view` を
  実行してください。
- **ダッシュボードが表示通貨を求める。** フォルダ内の帳簿の通貨が異なります。
  [価格と通貨](iris-view.md#価格と通貨)の方法で設定してください。
- **読み込めない帳簿があると表示される。** その帳簿で `iris validate` を実行すると
  理由がわかります。2つのフォルダが同じ帳簿のコピーだと表示された場合は、最初の
  1つだけが表示されます。フォルダにはコピーを1つだけ置いてください。
- **記帳や保存で、同期の実行中と表示される。** 同期か、別のウィンドウでの保存が
  その瞬間に帳簿を使っています。もう一度お試しください。

## それでも解決しないとき

- [基本コンセプト](concepts.md) を読み直してください。混乱の多くは `status`
  （下書きと記帳済の違い）か、同期が何をするかに由来します。
- 帳簿内の `notes/open-questions.md` を確認してください。AI は曖昧な項目をそこに
  記録します。
- 地域ごとの税のルールは、[オーバーレイ](https://irisbooks.io/docs/ja/overlays/)の地域ガイドを参照してください。
  変わりうる値（税率・各種表・申告様式）は、AI が税務当局の現行ページで確認します。
- ここまでで解決しない場合は、[Discord コミュニティ](https://discord.gg/wZDsv9gyb9)で
  質問してください。実行したコマンドと表示されたメッセージを添えると伝わりやすく
  なります。帳簿の中身（金額や取引先）は貼らないでください。回答は保証していません。

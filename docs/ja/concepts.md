# 基本コンセプト

IrisBooks の基本的な考え方を、短くまとめて説明します。ここを押さえると、CLI も
Web アプリも迷わず使えます。分からない語が出てきたら、ページ末の
[用語集](#用語集)で確かめてください。

## ファイルがあなたの帳簿

**帳簿**は、パソコンにある1つのフォルダです。その中のファイルが、会計記録
そのものです。ファイルは普段使っているツールで読めます。編集、変更箇所の比較、
バックアップ、税理士への受け渡しも同じです。CLI はこのファイルを読み書きし、
Web アプリはクラウドに同期したコピーを扱います。

1冊の帳簿が扱うのは1会計年度です。事業と家計を別々の帳簿にし、選んだ帳簿を
横断して集計できます。年度末には、この帳簿をコピーして翌年度の帳簿を
作ります（[帳簿は1年に1冊](#帳簿は1年に1冊)）。

```text
your-book/
├── config/
│   ├── book.yaml                 # 識別情報・地域・会計年度・通貨
│   ├── chart-of-accounts.yaml    # 勘定科目
│   ├── rules.yaml                # 任意の分類ヒント
│   └── overlays/                 # 任意: この帳簿独自の地域ルール
├── raw/                          # 元資料（CSV・PDF・領収書）
├── journals/YYYY-MM/             # 1仕訳 = 1 Markdown ファイル
├── assets/YYYY/                  # 固定資産（減価償却用）
├── filings/                      # 申告用の集計値の記録
├── notes/                        # 作業ノート・todo・方針・パースキャッシュ
└── compiled/                     # AI 生成レポート（再生成可能）
```

フォルダ構成の全体は [帳簿ファイル形式リファレンス](book-format-reference.md) にあります。

## 仕訳 — 取引

取引は1件ごとに1つの**仕訳**として記録します。仕訳は Markdown ファイルで、先頭に
YAML 形式の項目が付き、`journals/YYYY-MM/YYYY-MM-DD-<取引先>-NN.md` に保存されます。フォルダ名は日付の年と
月、つまり日付の先頭7文字です。複式簿記なので、借方と貸方は必ず一致します。

```markdown
---
date: 2026-05-04
payee: EXAMPLE.COM
status: draft
lines:
  - account: 資産:売掛金
    debit: 97000
  - account: 費用:支払手数料
    debit: 3000
  - account: 収益:売上
    credit: 100000
---

EXAMPLE.COM のリデザイン案件、5月分の請求（プラットフォーム手数料3%を差し引き）。
```

`---` の下のテキストは自由記述です。取引が起きた*理由*を書きます。ファイル名は
その仕訳の恒久的な識別子で、ステータスが変わっても変わりません。

## 勘定科目 — 勘定科目表

勘定科目は `config/chart-of-accounts.yaml` にあり、それぞれ階層パス
（`資産:普通預金`、`費用:消耗品費`）と種別（資産 / 負債 / 資本 / 収益 / 費用）を
持ちます。仕訳はパスで科目を参照します。科目の「通常残高がどちら側か」は種別から
導かれるので、自分で宣言する必要はありません。

科目には**エイリアス**を付けられ、別の言語や短い名前で参照できます。勘定科目表に
ない科目を、仕訳の中だけで使わないでください。先に勘定科目表へ追加します。AI には、
追加したい科目を `notes/open-questions.md` で提案してもらえます。

## ステータス — 仕訳のライフサイクル

すべての仕訳は `status` を持ちます。

| ステータス | 意味 |
| --- | --- |
| `draft` | 下書き。入力中、またはまだ不確実。まだ帳簿には載っていません。 |
| `posted` | 記帳済。既定のレポートに含まれます。 |

**`iris balance`・損益計算書・貸借対照表は、既定では記帳済の仕訳だけを
集計します。**下書きも含めた数字を見たいときは `--include-drafts` を付けます。
これは確認のための表示で、記帳は行いません。出力には、下書きを含んでいることが
示されます。確認した仕訳の記帳は [`iris post`](cli-reference.md) か、`status`
フィールドの書き換えで行います。

このほかに `closed`（Web アプリでは「締め済み」）という表示もあります。これは、
日付が締め済みの会計年度に入っている仕訳を表します。ファイルに保存される値ではなく、
表示するときに導き出される状態です。Web アプリ・`iris search`・リモートコネクタが
表示します。年度を再オープンすると、ファイルに保存されている本来のステータスが
表示されます。Web アプリでは、内容がそろっていない下書きに `incomplete`（画面では
「未確定」）の印も付きます。

## レポートは計算結果であり、保存されない

IrisBooks は「貸借対照表ファイル」を保存しません。レポートは、要求のたびに
記帳済の仕訳から導出されます。

- **試算表** — `iris balance` または `iris report tb`
- **損益計算書** — `iris report pl`
- **貸借対照表** — `iris report bs`
- 科目別の**元帳** — `iris report ledger --account …`

計算結果なので、常に元の仕訳と整合します。Web アプリでは同じレポートを画面で見られ、
それぞれ CSV に書き出せます。

## 元資料と相互参照

`raw/` に置いた銀行の CSV、領収書の写真、PDF の請求書などは、仕訳の根拠になる
**元資料**です（画面では「証憑」と表示されます）。仕訳は `attachments` で元資料を
指し、このつながりはどちらの向きにもたどれます。

- 仕訳から、それが引用する資料を見る。
- 資料から、それを引用する仕訳を見る（`iris references <path>`、または Web アプリの
  元資料ブラウザの「引用元」パネル）。

そのため、あなたも税理士も監査人も、仕訳から元資料へ、元資料から仕訳へ
たどれます。訂正・削除の履歴や検索など、ほかの記録まわりの機能は
[記録の履歴と年度締め](records-and-year-end.md) を参照。

## 地域のルール — オーバーレイ

`iris` のエンジンが知っているのは複式簿記だけで、特定の国の税法は知りません。
税や償却のように地域で変わるチェックと計算は、帳簿に追加する部品として配布します。
これを**オーバーレイ**と呼びます（`iris view` の画面では「プラグイン」、配布の単位は
「パッケージ」です）。中身は、人が読める形式（YAML と、CEL という式の言語）で書かれた
ルールと計算（**レシピ**）です。バージョンを固定し、機能ごとに選択します。仕訳の
貸借を補完するような共通の機能も、地域ごとの税や償却の機能も、それぞれ別に選びます。
定義・ガイド・例は公開リポジトリで確認できます。地域ごとのパッケージと、パッケージに
含まれない作業は、[オーバーレイのドキュメント](https://irisbooks.io/docs/ja/overlays/)で説明しています。

帳簿は `config/book.yaml` で、使う公開バージョンを固定します（例）。

```yaml
overlays:
  - journal-balance@2026.10.1
  - inventory-disposal@2026.10.1
```

地域のパッケージも同じ一覧に加えます。選択した機能は、そのバージョンの検証済みの
コピーが帳簿の中にある必要があります。選択は自分でも AI でも変更できます。帳簿独自の
ルールを作ることも、改善をコミュニティに提案することもできます。

- **ルール**はローカルの `iris validate` で仕訳をチェックします。クラウドは
  オーバーレイの定義と結果を保存するだけで、ルールは実行しません。
- **レシピ**は地域固有の数値（償却表や税の申告に必要な集計値）を計算し、
  出どころ（オーバーレイのバージョンと入力値）と一緒に、資産ファイルや
  `filings/` に記録します。`iris validate` がレシピを再計算するので、入力から
  導けなくなった数値は検出されます。
- **固定したバージョンが勝手に変わることはありません。** 新しいバージョンでは
  チェックや計算の内容が変わることがあるため、移行はあなたが決めたときに
  `iris overlay upgrade` で明示的に行います。古いバージョンで記録した数値は、
  引き続きそのバージョンで照合されます。

`overlays` を書かないか空にすると、追加の機能は何も動きません。その場合も、基本の
チェック（貸借の一致、勘定科目の存在、日付、金額）は動きます。帳簿の地域を設定した
だけで、オーバーレイが自動的に有効になることはありません。

公開オーバーレイはオープンソース（Apache-2.0）で
[github.com/irisbooks/overlays](https://github.com/irisbooks/overlays) にあります。
どの数値についても、根拠になったルールそのものをあなたや税理士が読めます。
`config/book.yaml` に書くバージョンは、このリポジトリのタグ名です。帳簿独自のルールを `config/overlays/` に
加えることもできます。詳しくは [帳簿ファイル形式リファレンス](book-format-reference.md)
を参照してください。

## 同期 — 3つの働き方

帳簿の使い方は3通りあります。モードを切り替えるわけではなく、使う機能の範囲が
違うだけです。

- **オフライン。** ファイルのみ、サーバーなし、アカウント不要。検証・レポートを
  ローカルで行い、[`iris view`](iris-view.md) で画面から見る・記帳する・編集する
  こともできます。データはパソコンの外に出ず、ネットワークも要りません。
- **ファイル + クラウド。** ローカルのファイルに加えて、クラウドにそのコピーを
  持ちます（`iris api login` でサインイン）。編集はローカルで行い、`iris sync` で
  クラウドと送受信します。Web アプリ、複数の端末からのアクセス、共同作業、日時付きの
  履歴は、クラウドのコピーを使います。
- **クラウドだけにアクセス。** ローカルフォルダなしでも、クラウドのコピーを
  閲覧・レビューできます。記帳作業は、税理士の方も、自分の AI と帳簿ファイルで
  行うことを勧めます。その際は、顧客ごとに作業フォルダとセッションを分けてください。

同期は**指示したときだけ**行われます。あなたか AI が `iris sync` か `iris post` を
実行するまで、ローカルのファイルはアップロードされません。ファイルを監視して裏で
送る仕組みはありません。一方、Web アプリでの変更は、直接クラウドに保存されます。
事業主も税理士も、同じ帳簿のコピーをそれぞれ同期し、Web で閲覧・レビューできます。

## 帳簿は1年に1冊

1つの帳簿は1会計年度分で、`config/book.yaml` の `fiscal_year` に記録されます。
年度が終わったら、[`iris yearend`](cli-reference.md#iris-yearend) で翌年度の
帳簿を**コピー**として始めます。この帳簿と同じ階層に新しいフォルダができ、
設定・勘定科目表・ルール・ガイド・ノート、まだ保有している固定資産、そして
この年度の期末残高から計算した期首残高の仕訳が入ります。新年度の日付ですでに
記録した仕訳は新しい帳簿へ移ります。クラウドにある帳簿なら、同じ手順で新しい
帳簿のクラウド側も作られます。同じメンバーがアクセスでき、受信アドレスも新しい
帳簿へ移ります。

作成後、2つの帳簿の間につながりはありません。古い帳簿はそのまま残るので、その年度の
申告はそちらで済ませてから締めます。日々の作業は新しい帳簿で行います。年度ごとに
勘定科目表や設定を変えても、もう一方には影響しません。AI が見るのは作業中の年度
だけで、保存の必要がなくなった年度は単独で削除できます。

## 年度の締め（Seal）— 年度を「見える形で」ロックする

年度末には会計年度を**締め**ます（`iris seal`）。サーバーが誰がいつ締めたかを
記録します。ロックの対象は、その年度の日付の仕訳と、帳簿の `config/`・`assets/`・
`filings/`・`compiled/` のファイルです。`iris post` は締め済み年度の仕訳を拒否し、
同期・Web アプリ・リモートコネクタからの対象ファイルの変更もサーバーが拒否します。
年度内の仕訳はどこでも `closed` として表示されます。元資料の `raw/` と作業ノートの
`notes/` は引き続き変更できます。ローカルのファイル自体は編集できますが、
ロック対象の変更を同期するには年度の再オープンが必要です。

締め済み年度を修正するには [`iris reopen`](cli-reference.md) で**再オープン**します
（Web アプリのボタンは「再開」）。
再オープン後にロック対象を変更すると、訂正・削除の履歴に**締め後の編集**として
記録され、この印はあとから消せません。`raw/` と `notes/` の変更には通常の履歴が残り、締め後の印は付きません。
修正が終わったら再度締めます。新しい締めが古い締めに代わり、古い締めも履歴に残ります。
締めによってファイルが削除されることはありません。
[年度締め](records-and-year-end.md#年度締め) を参照。

## 恒久的な履歴（訂正・削除の履歴）

クラウド同期を使うと、サーバーがすべてのファイルのすべての変更を記録します。
記録するのは、誰が、いつ変更したかと、変更前の内容です。記録は追加されるだけで、
あとから書き換えられません。これが**訂正・削除の履歴**です。
`iris api history`、または Web アプリの**アクティビティ**タイムラインと
仕訳ごとの**履歴**パネルで確認できます。
帳簿の（つまりその会計年度の）記録は `iris api history --all --json` で
ファイルに書き出せます。

ローカルの git 履歴はその代わりになりません。手元のパソコンにあり、書き換えも
できるため、独立した記録ではないからです。恒久履歴をサーバー側に置いているのは
そのためです。

## CLI・iris view・Web アプリの使い分け

| | CLI + 自分の AI | `iris view` | Web アプリ |
| --- | --- | --- | --- |
| 主な用途 | 事業主・税理士が AI とファイルで作業 | 自分のファイルを画面で見て、記帳・修正する | 閲覧・レビュー・クラウドの管理 |
| 編集 | AI がファイルを書き、あなたがレビュー | 下書きと記帳済の仕訳をフォームかソースで編集し、ファイルに保存 | 下書きの承認のみ |
| オフライン動作 | 可 | 可 | 不可（サーバー必要） |
| レポート | `iris report …`（テキスト/JSON） | ファイルから描画 | 描画 + CSV |

どれか1つを選ぶものではありません。CLI と AI で素早く入力し、`iris view` で
画面から確認して記帳し、Web アプリで共有とサーバーの履歴を加えます。

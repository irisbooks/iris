# 基本コンセプト

IrisBooks を理解するための考え方を手短に巡ります。これらが腑に落ちると、
CLI も Web アプリも自然に使えるようになります。

## ファイルがあなたの帳簿

隠れたデータベースはありません。**帳簿**はディスク上のフォルダであり、その中の
ファイルが会計記録そのものです。あなたはそれを読み、編集し、差分を取り、
バックアップし、普段使っているどんなツールでも税理士に渡せます。IrisBooks
（CLI と Web アプリ）は、そのフォルダを見る2つのレンズにすぎません。

1帳簿 = 1事業・1会計年度です。副業を持つ個人事業主が帳簿を2つ持つのは普通の
ことです。年度末には、この帳簿のコピーとして翌年度の帳簿が始まります —
[帳簿は1年に1冊](#帳簿は1年に1冊) を参照。

```text
your-book/
├── config/
│   ├── book.yaml                 # 識別情報・地域・会計年度・通貨
│   ├── chart-of-accounts.yaml    # 勘定科目
│   ├── rules.yaml                # 任意の分類ヒント
│   └── overlays/                 # 任意: この帳簿独自の地域ルール
├── raw/                          # 元資料（CSV・PDF・領収書）
├── journals/YYYY-MM/             # 1仕訳 = 1 Markdown ファイル
├── assets/YYYY/                  # 固定資産（減価償却用）
├── filings/                      # 申告用の集計値の記録
├── notes/                        # 作業ノート・todo・方針・パースキャッシュ
└── compiled/                     # AI 生成レポート（再生成可能）
```

全レイアウトは [帳簿ファイル形式リファレンス](book-format-reference.md) に。

## 仕訳 — 取引

すべての取引は1件の**仕訳**で、`journals/YYYY-MM/YYYY-MM-DD-<取引先>-NN.md`
に YAML ヘッダ付きの Markdown ファイルとして保存されます。フォルダ名は日付の年と
月、つまり日付の先頭7文字です。複式簿記なので、借方と貸方は必ず一致します。

```markdown
---
date: 2026-05-04
payee: EXAMPLE.COM
status: draft
lines:
  - account: 資産:売掛金
    debit: 89790
  - account: 資産:事業主貸
    debit: 10210
  - account: 収益:売上
    credit: 100000
---

EXAMPLE.COM のリデザイン案件、5月分の請求。
```

`---` の下のテキストは自由記述です。取引が起きた*理由*を書きます。ファイル名は
その仕訳の恒久的な識別子で、ステータスが変わっても変わりません。

## 勘定科目 — 勘定科目表

勘定科目は `config/chart-of-accounts.yaml` にあり、それぞれ階層パス
（`資産:普通預金`、`費用:消耗品費`）と種別（資産 / 負債 / 資本 / 収益 / 費用）を
持ちます。仕訳はパスで科目を参照します。科目の「通常残高がどちら側か」は種別から
導かれるので、自分で宣言する必要はありません。

科目には**エイリアス**を付けられ、別の言語や短い名前で参照できます。仕訳の中で
新しい科目パスを勝手に作らないでください。先に勘定科目表へ追加します（あるいは
AI に `notes/open-questions.md` で提案させます）。

## ステータス — 仕訳のライフサイクル

すべての仕訳は `status` を持ちます。

| ステータス | 意味 |
| --- | --- |
| `draft` | 下書き。入力中、またはまだ不確実。まだ帳簿には載っていません。 |
| `posted` | 記帳済み。**レポートに載るのは記帳済みの仕訳だけです。** |

最も重要なルールがこれです。**`iris balance`・損益計算書・貸借対照表に含まれる
のは記帳済みの仕訳だけ。**下書きは、記帳するまで各種レポートや残高に反映
されません。記帳は [`iris post`](cli-reference.md) か、`status` フィールドの
書き換えで行います。

（このほかに `closed`（Web アプリでの表示は「締切済」）も目にします。日付が
締め済み会計年度に入っている仕訳のことで、ファイルには保存されない導出値です。
Web アプリ・`iris search`・リモートコネクタのすべてがこれを表示します。年度を
再オープンすれば、保存されている本来のステータスがまた見えます。Web アプリでは
さらに、未完了の下書きを示す `incomplete` マーカーも出ます。）

## レポートは計算結果であり、保存されない

IrisBooks は「貸借対照表ファイル」を保存しません。レポートは、要求のたびに
記帳済みの仕訳から導出されます。

- **試算表** — `iris balance` または `iris report tb`
- **損益計算書** — `iris report pl`
- **貸借対照表** — `iris report bs`
- 科目別の**元帳** — `iris report ledger --account …`

計算結果なので、常に元の仕訳と整合します。Web アプリは同じレポートをグラフィカル
に描画し、それぞれ CSV に書き出せます。

## 元資料と相互参照

`raw/` 配下のもの — 銀行CSV、領収書写真、PDF 請求書 — は仕訳の*証憑*です。仕訳は
`attachments` で出所を指し、そのリンクは双方向にたどれます。

- 仕訳から、それが引用する資料を見る。
- 資料から、それを引用する仕訳を見る（`iris show <path>`、または Web アプリの
  元資料ブラウザの「引用元」パネル）。

この双方向の相互参照は、日本の優良電子帳簿が求める3要件の1つです。
[日本の税務・コンプライアンス](japan-tax-and-compliance.md) を参照。

## 地域のルール — オーバーレイ

`iris` のエンジンが知っているのは複式簿記であって、特定の国の税法ではありません。
国ごとに異なる部分は**地域オーバーレイ**にあります。明細行の税をどう区分するか、
使える減価償却の方法と特例、その上限、申告の集計値を帳簿からどう組み立てるか、
といった部分です。地域オーバーレイは、YAML と CEL で書かれたルールと計算
（**レシピ**）を地域ごと・バージョンごとにまとめたものです。最初に用意された
地域は日本で、日本の帳簿では消費税の税区分、減価償却の特例とその上限、定率法が
いつ改定償却率に切り替わるか、消費税申告の集計値を扱います。

帳簿は `config/book.yaml` で、使うバージョンを 1 つ固定します（日本の帳簿の例）。

```yaml
region: JP
overlay: jp@2026.09.1
```

- **ルール**は仕訳をチェックします。`iris validate` が実行し、クラウドも
  書き込みのたびに同じバージョンで実行します。
- **レシピ**は地域固有の数値（定率法の償却表や消費税申告の集計値）を計算し、
  出どころ（オーバーレイのバージョンと入力値）と一緒に、資産ファイルや
  `filings/` に記録します。`iris validate` がレシピを再計算するので、入力から
  導けなくなった数値は検出されます。
- **固定したバージョンが勝手に変わることはありません。** 新しいバージョンでは
  チェックや計算の内容が変わることがあるため、移行はあなたが決めたときに
  `iris overlay upgrade` で明示的に行います。古いバージョンで記録した数値は、
  引き続きそのバージョンで照合されます。

まだオーバーレイの無い地域の帳簿には `overlay:` の行がなく、普遍的なチェック
（貸借の一致、勘定科目の存在、日付、金額）だけが行われます。その地域の
オーバーレイが公開されたら、`iris overlay upgrade` で固定できます。

公開オーバーレイはオープンソース（Apache-2.0）で
[github.com/irisbooks/overlays](https://github.com/irisbooks/overlays) にあります。
どの数値についても、根拠になったルールそのものをあなたや税理士が読めます。
そこのタグ名が、固定に書く値です。帳簿独自のルールを `config/overlays/` に
加えることもできます。詳しくは [帳簿ファイル形式リファレンス](book-format-reference.md)
を参照してください。

## 同期 — 3つの働き方

同じ帳簿は3つの形態で存在できます。「モード」を選ぶのではなく、機能を多く使うか
少なく使うかの違いです。

- **オフライン。** ファイルのみ、サーバーなし、アカウント不要。検証・レポートを
  ローカルで行います。プライバシー最大、ネットワーク不要。
- **ファイル + クラウド。** ローカルファイル + クラウドミラー（`iris api login`
  でサインイン）。ローカルで編集し、`iris sync` で push / pull します。
  Web アプリ・複数端末・共同作業・タイムスタンプ付き履歴はクラウド側にあります。
- **クラウドのみ（税理士に多い）。** ローカルフォルダなし。Web アプリで
  サーバーに対して直接作業します。

同期は**明示的**です。あなた（または AI）が `iris sync`・`iris post` を
実行するまでローカルのファイルはアップロードされません。Web アプリでの変更は
直接クラウドに保存されます。裏で勝手にファイルを送るウォッチャーはありません。ノート PC から同期する事業主と、Web アプリで作業する
税理士は、同じサーバー帳簿で出会います。

## 帳簿は1年に1冊

1つの帳簿は1会計年度分で、`config/book.yaml` の `fiscal_year` に記録されます。
年度が終わったら、[`iris yearend`](cli-reference.md#iris-yearend) で翌年度の
帳簿を**コピー**として始めます。この帳簿と同じ階層に新しいフォルダができ、
設定・勘定科目表・ルール・ガイド・ノート、まだ保有している固定資産、そして
この年度の期末残高から計算した期首残高の仕訳が入ります。新年度の日付ですでに
記録した仕訳は新しい帳簿へ移ります。クラウドにある帳簿なら、同じ手順で新しい
帳簿のクラウド側も作られます。同じメンバーがアクセスでき、受信アドレスも新しい
帳簿へ移ります。

作成後、2つの帳簿の間につながりはありません。古い帳簿はそのまま残るので、その年度の
申告はそちらで済ませてから締めます。日々の作業は新しい帳簿で行います。年度ごとに
勘定科目表や設定を変えても、もう一方には影響しません。AI が見るのは作業中の年度
だけで、保存の必要がなくなった年度は単独で削除できます。

## 年度の締め（Seal）— 年度を「見える形で」ロックする

年度末には会計年度を**締め**ます（`iris api seal`）。サーバーが誰がいつ締めたかを
記録します。ロックの対象は、その年度の日付の仕訳と、帳簿の `config/`・`assets/`・
`filings/`・`compiled/` のファイルです。`iris post` は締め済み年度の仕訳を拒否し、
同期・Web アプリ・リモートコネクタからの対象ファイルの変更もサーバーが拒否します。
年度内の仕訳はどこでも `closed` として表示されます。元資料の `raw/` と作業ノートの
`notes/` は引き続き変更できます。ローカルのファイル自体は編集できますが、
ロック対象の変更を同期するには年度の再オープンが必要です。

締め済み年度を修正するには [`iris reopen`](cli-reference.md) で**再オープン**します。
再オープン後にロック対象を変更すると、監査証跡に**締め後の編集**として恒久的に
記録されます。`raw/` と `notes/` の変更には通常の履歴が残り、締め後の印は付きません。
修正が終わったら再度締めます。新しい締めが古い締めを監査チェーン上で引き継ぎます。
締めによってファイルが削除されることはありません。
[年度締め](japan-tax-and-compliance.md) を参照。

## 恒久的な履歴（訂正・削除の履歴）

クラウド同期を使うと、サーバーが全ファイルの全変更を追記専用ログに保持します —
誰が、いつ、変更前は何だったか。これが優良電子帳簿で日本の法令が求める
**訂正・削除の履歴**です。`iris api history`、または Web アプリの
**アクティビティ**タイムラインと仕訳ごとの**履歴**パネルで確認できます。
帳簿の（つまりその会計年度の）記録は `iris api history --all --json` で
ファイルに書き出せます。

ローカルの git 履歴はこれには*該当しません*。監査人が信頼できるのはサーバー側の
記録だけであり、これが恒久履歴がクラウド側にある理由です。

## 2つのレンズの比較

| | CLI + 自分の AI | Web アプリ |
| --- | --- | --- |
| 向いている人 | ファイルファーストの事業主、自動化 | GUI 派の事業主、税理士 |
| 編集 | AI がファイルを書き、あなたがレビュー | ブラウザのフォーム |
| オフライン動作 | 可 | 不可（サーバー必要） |
| レポート | `iris report …`（テキスト/JSON） | 描画 + CSV |

二者択一ではありません。多くのユーザーは両方を使います。CLI + AI で素早く
入力し、Web アプリでレビュー・レポート・共同作業をします。
